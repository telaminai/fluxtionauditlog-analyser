2. F1 · `context` DID NOT CARRY THE VERDICT IN THE CASE THE FEATURE EXISTS FOR — fixed here
================================================================================
The report says: "Surfaced in context.topology.auditLogging, verified live with a graph loaded and NO
log open." On the branch as pushed that is false. With a graph open and no log ever loaded, `context`
returned {project, filter} and nothing else — for all three graphs above.

Cause: MainFrame.context() returns early when `filter == null` (a fresh start), and
`out.put("topology", topologyPanel.cursorState())` sat 49 lines BELOW that return. The verdict was in
cursorState() correctly; context() never reached it. The `topology` VERB echoes cursorState() directly,
which is almost certainly what was verified live — it does carry the verdict. So the claim is true of the
verb and false of `context`, and `context` is the one an agent calls first.

This is the same trap M37 found for `source` (it too sat below the early return, so a --rest fresh start
reported no roots). Fixed here the same way: the topology block moved above the return. Re-verified on
the rebuilt jar: graph open, no log → context.topology.auditLogging present. The report's sentence
should be corrected to say what was actually verified.

Worth a sentence in the ledger or ONBOARDING: context()'s early return has now hidden two facts from
agents that the code "put" correctly. Anything added to context() must go ABOVE it unless it genuinely
depends on a loaded log.
