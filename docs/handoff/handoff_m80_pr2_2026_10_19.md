## Contract and code

- `BuilderDocument` indexes only the lexical `buildGraph` body, under the existing 2 MiB UTF-8 limit.
  A literal name on a two-argument `addNode`/`addPublicNode` anchors the call token's line, including
  wrapped calls. Computed, missing, concatenated, text-block and trailing varargs names are not invented.
  Nested constructor sites are labelled `discovered, no name`, not asserted to be runtime graph members.
  Comments, strings, character literals and text blocks cannot manufacture registrations.
- `DesignWorkspace`, `DesignSession` and the existing Design sidebar expose these locations. The
  existing `source {bean}` selector matches XML ids or unique literal Java node names; duplicates
  refuse rather than choosing one. XML's released echo values and order remain unchanged. `nodes`
  uses the already approved additive key; no new key or parameter is introduced in this PR.
- `source:design:node:<id>` is a permanent synonym in `DESIGN_BEAN`, not a second family. The owner
  separately approved the exact three metadata edits pinned by `M80DesignApiDeltaTest`. That test
  retains eleven literal pre-change hashes and proves that removing only those edits restores them.
  Historical API-delta tests retain their original hashes, undoing this independently pinned later delta.
- Follow observations are facts. `DesignSession` accepts or retires `FollowReadCompleted` and requests
  `PresentDesignRefreshEffect`; the adapter no longer predicts acceptance by comparing an old generation
  after the accepted read increments it. Accepted failures present their qualification and keep the last
  good revision. A named declaration can rebind uniquely; an edited line anchor retires.
- The public builder API was read with `javap` from `fluxtion-builder-api` 1.1.2: named two-argument
  registrations and the unnamed/varargs overloads are distinct. This is a bounded lexical location aid,
  not Java overload resolution, a helper-method analyser, generation, or evidence that source matches a run.
