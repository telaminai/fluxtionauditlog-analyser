3. DEFECTS CAUGHT BY MY OWN FIRST TEST RUNS (test-first working as intended)
================================================================================
  - M29.1 reorder count compared each row to its PREDECESSOR; 3000,1000,2000 counted 1 not 2.
    Running-max is the honest metric (any row below the high-water mark is out of order). Fixed
    before commit; the verb test then re-verified the same semantics end-to-end.
  - M30.1 probe loop was INVERTED for files smaller than the window (`window/2 < size` never ran)
    — every fixture probed null. Rewritten probe-at-least-once. This is the exact bug class the
    corrected D-R6 warns about: a mechanism that defeats its own intent, caught only by running.

4. DECISIONS BEYOND THE SPECS' LETTER (flag in review)
================================================================================
D1  (M29) Refused/failed external items are WARNINGS, not call failures — the M28.5 contract
    (apply the valid remainder, name the skipped). Acceptance 4's "refused loudly" is satisfied by
    the warning naming rule + setting + directory; a hard fail would hold the rest hostage.
D2  (M29) The verb LOADS before the EDT apply so the echo is the loader's own report; the UI path
    stays async (Background). Two entry points, one applyExternalLoaded seam.
D3  (M30) The probe bound: 256KB doubling to 4MB, then "no timed record in the probed head —
    positioned by name, order unverifiable". A file whose first timed record sits past 4MB is
    treated as untimed FOR ORDERING; the message names the boundary honestly. Full-scan ordering
    was rejected: discovery must not read gigabytes before the user has even agreed to open a set.
D4  (M30) Snapshot.rowForOffsetInFile / floorRowInFile are LINEAR over the file's rows — member
    ranges are contiguous so a binary search per range is possible, but offsets-in-file lookups are
    rare (one per verb call) and the linear form stays correct even if contiguity ever changes.
D5  (M30) D-R4 caveats ride goto {at} and series. read {at} does NOT carry the note: read is
    dispatched directly to ReadService (dispatcher-side), and threading a report supplier through
    ActionDispatcher's three construction sites for one note was judged not worth the surface —
    'context'.timeOrder and the load dialog carry the full report. RECORDED AS A DEVIATION from
    D-R4's letter ("time-anchored features carry the note"), not hidden. Cheap to add if review
    disagrees.
D6  (M30) The "banner" is a status-line suffix plus a once-at-load WARNING DIALOG listing the
    violations; the spec's clickable go-to-violation links are NOT built (deviation, recorded).
    The violation lines carry record anchors, so goto reaches them today; the clickable UI is a
    small follow-up slice if wanted.
D7  (M30) Follow on a composite: unsupported (supportsFollow false), per the spec non-goal; the
    single-file follow path is untouched.
D8  (M29) The dialog's format combo is editable (a DateTimeFormatter pattern can be typed) but only
    the three named formats are offered — patterns are the escape hatch, not the path of least
    resistance.
