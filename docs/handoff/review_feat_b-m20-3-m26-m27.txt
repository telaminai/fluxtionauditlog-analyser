F1  THE EXPORT SIDE DOES NOT DISCLOSE THAT FOCUSES RIDE "GRAPHS" (D5's consequence).
    D5 is a sound decision — focuses are the same kind of named analysis artifact as saved graphs,
    and widening the pinned five-category set deserves an owner decision rather than a side effect.
    The IMPORT side is honest: the preview summary appends "· N named focus(es)". The topology
    guide is honest: "Named focuses are saved with your project and shared like saved graphs."
    Two places are not:
      - docs/site/user-guide/sharing-setups.md still describes the category as
        "| Graphs | named graphs, their series, formulas, resolve policy and pinned windows |"
        with no mention of focuses. That page is the reference for what each category contains.
      - The export dialog's checkbox is Category.label, i.e. the bare word "Graphs". A user ticking
        it is not told focuses go too.
    Severity: LOW — a focus is node ids plus a rationale string, so this is a disclosure gap, not a
    leak, and nothing secret can ride the category. But it is precisely the drift class this repo
    has now caught four times (assistant.md's 12-vs-13 tools, its stale destructive paragraph, the
    manifest's six verbs, and this), and the established remedy is a test rather than vigilance —
    ManifestVerbContractTest is the pattern. One line in sharing-setups.md, and optionally
    GRAPHS("Graphs and named focuses", true), would close it.
