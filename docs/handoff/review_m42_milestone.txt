3. FINDINGS
================================================================================
F1 (low, correctness) — runningJar() copies EVERY pre-jar JVM option into the registered client
  command, including debug/instrumentation flags. A `java -agentlib:jdwp=…,address=5005 -jar app`
  launch would bake the debug flag into the bridge command; when the client later launches it, the
  port is taken (or suspend=y hangs the bridge silently at client startup — the worst kind of
  "MCP server doesn't respond"). JBang winning whenever installed keeps exposure low, and IDE
  launches are -cp (refused), but the fix is small: refuse form 2 (per the spec's own "safely
  identified" bar) or strip -agentlib/-javaagent/-Xdebug/-XX:+*Debugger options when present.
F2 (debt) — CodexMcpClient and ClaudeMcpClient are ~90% identical (findExecutable, invoke, drain,
  redact, quoteForShell, the record types). A third client CLI makes three copies of a process
  harness whose timeout/kill/redaction behaviour must never drift apart. Extract the shared
  CLI-runner on next touch.
F3 (nit) — section 2's "Ready to run…" box joins the vector with two spaces, unquoted; a path with
  spaces reads as separate arguments if someone copies from THERE rather than the quoted Copy
  actions. Cosmetic; consider shellDisplay for that box too.
F4 (nit) — the generic-setup screenshot clips the two-names note mid-sentence ("…identifies itself
  as"). Recapture taller when docs are next regenerated.
F5 (note, known class) — this dialog is modeless and paints UiTheme colours at build time, so it
  will not follow a Theme ▸ switch while open — the same accepted N2 gap recorded in the 3d27f3d
  review. Close/reopen; no action beyond this note.
F6 (note) — saysMissing() classifies ABSENT from CLI output substrings; a CLI version/locale change
  degrades it to INDETERMINATE, which the UI handles honestly. Fine as built; recorded so a future
  "always indeterminate" report has its likely cause named.
F7 (process) — the tracker's M42.5 line records "live MCPB contract verified" with no pointer to
  where that verification lives. Rule 1's own lesson: a recorded verification that stopped being
  true reads exactly like one that is. When M42.3/.4's final acceptances are recorded, name the
  evidence location (report file or ledger line) for the MCPB check too.
