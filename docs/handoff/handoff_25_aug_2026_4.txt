  1  AN AGENT-DRIVEN FRESH START (review N2 — M35.7's species one step earlier).
     Facts: REST is off by default and enabled only in Settings; a fresh install shows a MODAL
     "Welcome! No configuration was found" then the Settings dialog. So "fresh machine, only a JDK,
     an agent starts the analyser" — M19's own premise — cannot reach the socket at all.
     · `analyser --rest`: start with the REST transport ON. It persists (Settings ▸ Assistant shows
       it on) and SAYS so on stdout — an agent-enabled setting that survives is what the next human
       launch needs; silently persisting would be the sin, saying it is not.
     · Under `--rest` the first-run modal is NOT shown: a process asked, and a process cannot answer
       Settings. Print where the endpoint file is instead. Human launches are unchanged.
     · The MCP bridge's "analyser not running" error names the command that fixes it.
     · usage(), install.md, assistant.md updated in the same commit. CHANGELOG (user-visible).

  2  THE BENCH — tools/bench/, the §H harness, runnable TODAY with no Mongoose.
     · mongoose-stub.py: a fake server admin surface that does exactly what UP-MNG-01/02 ask of the
       real one and nothing more — writes the registry file (~/.mongoose/servers/<name> shape, mode
       600), serves GET /api/audit/files, GET /api/audit/file/{id}/export?format=yaml and
       GET /api/processors/{g}/{n}/graphml from the in-tree demo set. It is the CONTRACT in
       executable form: the mongoose-side work is "make the real server pass what the stub passes".
     · loop-bench.py: the AGENT of §C3 steps 3–7 as a script. Glob the registry → pick the server →
       check pid → export log + graphml → drive the analyser over REST: open {log, graphml,
       provenance: <name>}, source_root {add}, then ASSERT from context/coverage/topology that the
       loop closed (provenance = the server's name; records loaded; the graph fits; coverage
       answers). Every step PASS/FAIL by name; non-zero exit on any failure — "a break fails in the
       owning repo rather than in a user's session".
     · `--launch` starts the analyser itself from target/ with `--rest` into an ISOLATED home
       (-Duser.home), which also exercises slice 1 end to end on a never-configured install.
     · Pointed at a REAL registry directory it is the acceptance test for UP-MNG-01/02. Say so in
       the README. Where the bench must ASSUME something the real server has not decided (auth
       header shape), flag it as an assumption, never bake it in silently.
