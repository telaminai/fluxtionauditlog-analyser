3. P1 FINDINGS AND DECISIONS
================================================================================

F5 (BLOCKING P1 — D-X6 single model not implemented): bundle.ts is a useful grouping but not the typed
bundle model the signed handoff requires. mongoose.ts independently derives registry path, run/export/
stop commands, YAML path and README statements; bundle.ts separately derives the same artifact, YAML,
GraphML, commands, processor FQN and guide text. Tests assert today's duplicate strings agree, but a
future rename can update one emitter and leave another stale.

Required correction: resolve one immutable AnalyserBundleModel from a validated StarterSpec, containing
contract, server identity/environment, processor/FQN, source roots, concrete GraphML/YAML paths, commands,
selected skills and provenance. P0 scripts/README and P1 profile/guides/skill substitution all consume it.
Tests vary model inputs once and assert every emitted consumer follows; no consumer reconstructs paths.

F6 (BLOCKING selected example): the fixture imports mongoose-hosted-fluxtion.starter.json, whose Fluxtion
definition is imperative builder style. Tracker O2 resolved the M19 example in favour of Spring-XML so
tutorial part 4 can make a design-IR edit and follow the maintained build-with-AI → spring-authoring
skill/contract path. P3 cannot silently turn the convenient P0 fixture into the public example.

Required correction: make the actual analyser-bundle entry/fixture Spring-XML-defined and carry/reference
the relevant maintained authoring snapshot promised by M19.1. The generic P0 mechanics may keep an
imperative regression fixture, but it is not the downloadable M19 acceptance artifact.

F8 (BLOCKING P1 — PROFILE ABI; FOUND WHILE SCAFFOLDING P3): the generated profile looks plausible but
does not populate the analyser. ConfigStore.readList and readRunbooks iterate zero-based `0..count-1`.
P1 emits `sourceRoot.count=1` with only `sourceRoot.1`, so no root loads; it emits two runbooks as `.1`
and `.2`, so `.0` is refused/absent and `.2` is never visited. SettingsShare recognises processors only
through `eventProcessorFqn.count` + zero-based members (and `selectedEventProcessor`); the emitted singular
`eventProcessorFqn=<fqn>` is an unknown property. `projectName` is also not an analyser key; activeName is
derived from the canonical profile's project-root directory.

Required correction: consume `m19-bundle/3` at analyser `3720ef91704d675f1a98cf79d98829c2dd19c8c4`:
`share.version=1`, `sourceRoot.0..`, `eventProcessorFqn.count` + `.0..`, `selectedEventProcessor`, and
`runbook.0..`. Remove `projectName`. A real `ProjectProfile.load` regression now pins that exact shape.
No v2 bundle was published or accepted; m19-skills/1 and the P0 verdict are unchanged.

D1 REPLAY DEVIATION — ACCEPTED. m19-skills/1/D-X5 conditions replay on a bundle replay claim. This bundle
has no honest replay entry point. Shipping load-audit-log + run-mongoose-server covers open, run, export,
stop and regeneration without inventing a command. VENDORED.md records the omission. If replay is later
added, its skill and comparison acceptance become mandatory together.

D2 CONTRACT VERSION HOME — ANSWERED, NO PROFILE KEY. For m19-bundle/3, P3 parses the exact marker
`Bundle contract: **m19-bundle/3**` from required root CLAUDE.md, refuses unknown/missing versions, and

authority. This uses files/content P1 already emits; it adds no inventory item or profile schema key and
did not itself require the v3 bump — the profile ABI correction above did.

misses". That was true at review time and is closed on analyser main by 389d331. Update the stale comment;

4. P2 IS A REAL REMAINING SLICE
================================================================================

P1 statically imports two canonical files and emits canonical@6243a89. It does not implement the
m19-skills/1 build/release source contract:

  · canonical HTTPS, clean corporate HTTPS mirror, local air-gapped and literal none modes;
  · m19-skills/1/index.json parsing, contract/revision, unique contained paths and size/count bounds;
  · distinct none, not-found, invalid content/index and transport failure outcomes with no fallback;
  · mirror/local/none sanitised provenance, with no absolute local path or URL credentials;
  · name/description/x-analyser-min-version validation and refusal when minimum exceeds the analyser
    version the bundle names;
  · refusal of project-supplied skills.source as a generator input (the analyser already refuses it at
    runtime; P2 must prevent the project from steering build/release retrieval).

The canonical imports and grammar fixture can become the default P2 mode; they do not make the other
requirements disappear. Full P3 acceptance includes none, canonical and one non-canonical fixture, so
starting it before P2 would guarantee an incomplete matrix.
