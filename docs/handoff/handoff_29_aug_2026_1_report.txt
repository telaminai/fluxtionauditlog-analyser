DEFECT FOUND AND FIXED — the generated `MongooseMain` installed NO shutdown hook. It booted the
server and returned, leaving the JVM alive on non-daemon agent threads, so SIGTERM killed the
process without ever calling `MongooseServer.stop()` -> `Service.stop()`. Consequences: audit
capture was never closed cleanly, and the registry entry survived every "clean" stop exactly as if
the process had crashed. That made THREE shipped statements false at once — `stop-server.sh`'s own
echo, the README's stop line, and the canonical skill's step 5 ("so Chronicle capture closes
cleanly and the registry file is removed").

Worth noting for the record: my svc-admin-web `stop()` fix was correct all along and had been
verified against `admin-web-example` — which has an explicit shutdown hook. The generated bundle
did not, so the removal code was simply never reached. A static check could not have found this;
only running the artifact did.

Fixed in the generator (MongooseMain captures the server and stops it on a shutdown hook), pinned
by a test, and re-verified on the real bundle: boot -> registry published -> `./stop-server.sh` ->
"stopping Mongoose server..." -> registry entry REMOVED.
