3. MISMATCHES vs D-X1–D-X10 (observed → correction → owner → level)
================================================================================

M-1  Brief/§5 assume a Mongoose starter lives in the mongoose repo ("Mongoose M1/M3": keyless
     run contract, start/stop/regenerate entry points). Observed: those artefacts are EMITTED BY
     THE PLAYGROUND STARTER (fluxtion-web). Correction: reassign M1 and M3 to the playground;
     the mongoose side owns runtime capabilities only (audit backend + lifecycle, admin
     endpoints, registry publication). Ownership change only — no product change.

M-2  D-X3 "startup never requires a key when the generated processor is present": TRUE of the
     builder, FALSE of every current mongoose-hosted starter mode (§1.3). Correction: the bundle
     contract must specify AOT + committed generated source + regeneration NOT bound to the
     default lifecycle (behind a -Pgenerate-fluxtion profile, as some fluxtion templates already
     do). Owner: playground. Product-level: yes — it changes the generated pom shape and the
     starter's mode selection for bundles.

M-3  The bundle contract's "text file sink at ./logs/audit-<name>.yaml, pre-enabled" does not
     exist in Mongoose (chronicle-only capture; YAML is export-at-read). Three honest v1 routes:
       (a) adopt the EXPORT BEAT for the bundle (works today; it is the accepted dev-loop shape);
       (b) wait for/fund UP-RDR-01 (Chronicle reader — deletes the export beat);
       (c) new file-sink backend in mongoose (new runtime work; must not fight the single-slot
           LogRecordListener owned by the capture service).
     Owner decision required (this is also the bootstrap tracker's D-01, now answerable: no
     current config writes that file). Product-level: yes.

M-4  loop-bench parses GET /api/audit/files as {"files":[…]}; the live endpoint returns a bare
     array (and the svc-admin-web webapp consumes that shape). Recommended: the bench accepts
     both shapes (analyser-owned edit; the stub itself flags the listing shape as "UP-MNG-04's
     proposal"). Implementation-level. NOT patched around on the mongoose side.

M-5  loop-bench sends `Authorization: Bearer <token>` only when the registry says authMode
     "TOKEN". Real modes are NONE|BASIC|BEARER; the registry file now publishes the enum name and
     Bearer headers are honoured in BEARER mode. Recommended: bench maps BEARER → its TOKEN
     behaviour. Implementation-level, analyser-owned (the stub's own module doc invites this
     correction).

M-6  "Bundles are generated at Download time by the playground service" — mechanism is the
     user's BROWSER (client-side zip). The pinning semantic O3 wanted is preserved. Consequence
     for D-X8: prefer skills vendored into the repo at build time over any download-time fetch
     (§2.4). Product-level nuance for the contract text.

M-7  (Positive.) UP-MNG-01's registry file and UP-MNG-03's `environment` declaration now exist
     (section 4). The UP-MNG-03 REFUSAL half (non-dev refuses admin control) is deliberately NOT
     implemented: it presupposes the UP-MNG-02 admin-tool surface whose retain/defer/withdraw is
     an explicitly reserved owner decision (D-05 in the bootstrap tracker; A3 follow-up).
