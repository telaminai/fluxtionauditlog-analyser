================================================================================
P1 · BLOCKING, IN PRODUCTION — the bundle ships NO generated processor and NO GraphML
================================================================================
The live zip contains no `generated` directory, no `.graphml`, and no generated `.java` anywhere:

  find . -path "*generated*"   -> nothing
  find . -name "*.graphml"     -> nothing

Its own README says the opposite, verbatim:

  "**No API key is needed to build or run** - the generated processor ships in this project"

**It does not ship.** What follows was checked rather than inferred:

  * `mvn compile` SUCCEEDS. The processor is loaded reflectively by name in
    `MarketProcessorSupplier.get()`, so nothing fails at compile time and the defect is invisible to a
    build.
  * After that compile there is **no `MarketProcessor.class` under `target/`** - the class the server
    loads by name does not exist in any form.
  * So the failure lands at **server startup**, as
    `IllegalStateException("generated processor not found - run './mvnw package'")`.
  * And that advice is itself wrong: generation is behind the `-Pgenerate-fluxtion` profile, so
    `./mvnw package` will not produce it. The command that would is `./mvnw -Pgenerate-fluxtion package`,
    **which requires a Fluxtion API key.**

**Net effect: the keyless claim is false for the bundle currently in users' hands, and recovering costs a
key.** That is the headline promise of the whole M19 onboarding path, and a guided-start user following
the docs page meets it at the first `./run-server.sh`.

Consequences beyond the key:

  * **no GraphML -> no pairing, no coverage, no M40.1 verdict.** The analyser can open the log and cannot
    do the thing beat 2 of the guided tour exists for;
  * the shipped profile declares `selectedEventProcessor=com.example.myapp.generated.MarketProcessor`,
    a class that is not in the bundle;
  * the bench's day-two GraphML discovery check passes on the *declared* path while the file is absent -
    worth knowing when reading its output.

**Not a regression in the contract - a regression against it.** v3 already requires both artefacts, and
rounds 01-05 used a bundle that had them; agents read `MarketProcessor.java` directly. Something in the v4
generation path stopped emitting them.

**This is the playground's to fix, and it outranks everything else on their list.**
