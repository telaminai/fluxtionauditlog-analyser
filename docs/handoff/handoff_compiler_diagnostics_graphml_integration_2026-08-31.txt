Contract decisions now recorded once
------------------------------------

1. Java and Spring diagnostics use DiagnosticReport/FluxtionDiagnostic as one envelope. Spring S*/V*
   names are not a second transport shape: their semantic identifiers become diagnostic code values;
   subject becomes the tagged element; xpathHint remains an element property.

2. The diagnostic DTO remains in fluxtion-builder and Java-8 compatible. The published JSON schema is
   exercised with a real Draft 2020-12 validator. Remote transport is not implemented; the new Kryo
   registration-order test is a gate, not a claim that old/new released artefacts have been round-tripped.

3. Diagnostics now have a production-reachable, opt-in sidecar:
     -Dfluxtion.diagnostics.sidecar=<path>|true
   It writes warnings and a terminal DiagnosticException without changing the legacy exception text.
   A public collector seam and remote response carrier remain open.

4. The exporter is a serializer, not the semantic authority. Node facts come from NodeDto; reference
   field and push kind are recorded per relationship beside dependency discovery; propagation comes from
   the event graph; dispatch rank comes from TopologicallySortedDependencyGraphDto's recorded
   eventDispatchPositionMap. This preserves one source of truth and avoids choosing between two live graph
   orderings in the exporter.

5. GraphML metadata remains staged behind:
     -Dfluxtion.graphml.metadata=OFF|AGGREGATED|PARALLEL
   The default is OFF. Unknown or blank values are OFF. OFF uses the legacy edge path; the corrected
   edgedefault="directed" remains unconditional. PARALLEL must not become the default until a real consumer
   reads the keys.

6. A vertex pair may carry several relationships. PARALLEL emits one edge per relationship. AGGREGATED
   keeps one pair edge, lists compatible string facts, and omits a scalar boolean when relationships
   disagree rather than writing invalid GraphML such as false,true.

7. sourceFingerprint is a canonical model digest shared by GraphML, descriptor and generated-source
   metadata. Its input set is still to be decided. Graph/log pairing also needs the runtime audit artefact
   to carry that digest, but this compiler spec does not pre-decide whether that is a header, record or
   sidecar.

Review findings integrated
--------------------------

* Per-relationship propagation: a trigger and @NoTriggerReference sharing one node pair no longer share
  an OR'd answer.
* Per-relationship push kind: a push and ordinary reference sharing one pair keep distinct kinds.
* @OnEventHandler(ofType=...) uses the concrete dispatch type recorded in the DTO.
* topologicalRank is the recorded dispatch position, not object/field order; a push owner ranks before
  its target.
* Method-reference captures carry a labelled relationship.
* EventLogSource subinterfaces are audit-capable without falsely claiming base-class provenance.
* SERVICE_DEREGISTERED is present in the manifest and semantic manifest values are tested, not merely key
  identifiers.
* Metadata mode is captured once per export; it is not re-read partway through emission.
* Nodes and edges are emitted deterministically. The byte-stability check covers the whole GraphML rather
  than stripping a timestamp; generatedAt was removed pending an explicit reproducible-build policy.
* The sidecar is driven through Fluxtion.compile in a production-path test, rather than by directly testing
  the JSON writer.

Conflicts and their resolution
------------------------------

There were three tracker conflicts caused by the remote advancing during verification. Each was resolved
by retaining new evidence without reinstating stale architecture:

* The production sidecar replaced the old statement that no production writer exists.
* The runtime fingerprint carrier remains undecided rather than being silently fixed as an audit-log
  header.
* The last remote topological-rank fix selected getSortedDependents() in an exporter fallback. The
  integrated version keeps the stronger model-owned solution already present: the exporter consumes the
  DTO eventDispatchPositionMap. The remote's method-reference and deterministic-order tests were retained.
* Duplicate rank fixtures and a duplicated XML helper introduced by the textual merge were removed; the
  existing push fixture already pins dispatch rank, so one fixture now proves one claim.
