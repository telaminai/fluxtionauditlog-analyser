# Battery readiness: customer generation and revised recording

The changed-graph checkpoint passed through a published customer generation route. Client
compatibility and battery acceptance are separate gates; the results below do not replace public
acquisition, release publication, Spring reconciliation, or the held-out battery.

## Changed graph: verified, not ordinary packaging

The operator extracted the corrected preview analyser-bundle ZIP, added a `VolumeTotal` node
referencing `RootNode`, and added that bean to the Spring XML and `nodeBeans`. Its trigger accumulates
the input volume, writes `totalVolume`, and returns false. Before generation the operator froze the
five expected totals and a one-attempt limit. No client was given the solution or credential.

`./mvnw -B -Pgenerate-fluxtion package` completed in 10.228 seconds using the published BOM 1.0.71,
runtime 1.0.16 and Maven plugin 1.3.0. The configured customer RapidAPI route used the owner's
existing external credential; no private provider or locally built compiler artifact was installed.
The published builder service-provider inventory contains its HTTP model generator. This establishes
a provisioned customer route, not keyless regeneration or availability for every beta tester.

Generated Java now contains the new node and callback; generated GraphML contains `volumeTotal`.
The supported launch, audit export and stop helpers then succeeded. All five runtime totals matched
1,200 / 2,000 / 3,500 / 4,140 / 6,240. Port 8181 was closed after shutdown. The long-running launcher
exited 143 when the stop helper terminated its JVM; the stop helper exited zero.

## Refusal adjacency: association, not cause

[Raw-line analysis](evidence/battery-readiness-2026-09-20/refusal-adjacency.json) distinguishes
first refusal from final termination. Four of the five first refusals immediately followed a
journal-related call (including the helper invocation in trial 2). Across all eight refusal events,
five followed journal-related calls and three did not. The normally completed trial also made
thirteen journal-related calls and ended with a journal edit. This is insufficient to infer causality.

Trial 5 first refused at 82.25 seconds, then continued until roughly nine minutes. Its terminal
runtime is not its time to first refusal. The earlier 92-second smoke cannot establish compatibility
for longer tasks; equally, the terminal-duration table alone cannot locate the failure mode.
R2 stops on the first provider refusal rather than allowing later activity to blur the result.

## Frozen protocol

[R2](evidence/battery-readiness-2026-09-20/PROTOCOL.md), its prompts, predictions and
[rubric seal](evidence/battery-readiness-2026-09-20/protocol-seal.json) were frozen before any new
client started. Observable tool-event receipt times replace subject-authored timing. A short source
pointer remains declared attribution; observed file reads are separate evidence, not proof of why
an action was chosen. No journal or hidden reasoning is requested. No trial may be repaired mid-run.

Three positive trials use a pristine supported bundle each, six CSV scenarios, a deliberately wrong
expectation to test the checker, and two model levels on the same client/provider. One negative trial
tests the explicit no-launcher case. Each is a provisioned-project compatibility task, not T1.
The frozen duration gate requires three completed refusal-free trials of at least 240 seconds; a
faster functional pass does not qualify this gate. There is no deliberate time padding.

## PPF-2: another invented file reference found by the negative trial

The actual no-launcher download correctly declined in README and runbooks, but its hosted POM
comment still called the absent `run-server.sh` the supported launcher. R2-4 noticed the contradiction
and stopped rather than inventing a command from the IDE configuration. That is the recorded result.

After the trial completed, the author added an assertion to the script-disabled regression: the POM
must not name `run-server.sh` and must disclose that no command-line launcher was requested. It failed
on the tested emitter (36 passed / 1 failed), then all 521 tests passed after making the comment follow
`addRunScript` (playground `3bdcfbd`, pushed; preceding host guard `5b67224`). This is a separate
correction; the sealed fixture, transcript and outcome were not rewritten and no client was rerun. The two-name launcher selection still declines safely for unknown
names. Its list may be incomplete; its fallback must never invent a command.

## Evidence limits and next gate

The six historical trials remain a regression corpus for the scorer, not new product recurrence.
No new adoption ratio, v2-improvement claim or absence-of-authoring-traps claim follows from these
unchanged-source tasks. A battery still needs its exact public/preview target and capability provision,
T5 availability if scored, isolated held-out expectations, and the sealed T1–T6 prompts. In particular,
the operator's working credential does not establish a customer's key provisioning journey.

Raw projects, baseline, transcripts and runners are retained privately under the durable ignored
`.local-evidence/coldstart-v2-2026-09-20/battery-readiness/` archive. Published event projections omit
private thinking/signatures, retain raw-line references and operator receipt times, and apply rule-1
redaction. Never quote warm-cache durations as acquisition times.
