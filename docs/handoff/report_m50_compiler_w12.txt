ORIENT FIRST
  · docs/specs/spec-generated-dispatch-performance.md §18 (ANALYSER repo) — W12 diagnosed precisely.
    §18.2 is the part that matters: ONE asymmetry causes all three reflection sites. Auditors are
    registered onto the SEP as fields but never into nodeNameLookup, so every by-name lookup has to
    fall back to a reflective field probe. The fix is to close the asymmetry at generation time.

WHY IT IS WORTH DOING, AND IT IS NOT PERFORMANCE
  Round 58 could not run the graph under native-image until a hand-written reflect-config.json was
  supplied. That is an adoption tax paid by every native-image user, for a lookup the compiler could
  have resolved statically. Worse, the failure is at RUNTIME and says NoSuchFieldException, not at
  build time where a generator error belongs. This item removes the requirement rather than
  documenting it.

THE SOUNDNESS QUESTION, ASKED AND ANSWERED — attack this if you attack anything
  Reflection found ANY public field. The switch lists only auditors. That is a narrowing, and a
  narrowing can be a regression.

  It is not, because the switch is DERIVED from the same collection that declares the auditor fields
  and drives initialiseAuditor / tearDown / processingComplete / eventReceived. It is not a
  hand-maintained parallel list that can fall out of step; if a field is an auditor it is in the
  switch, by construction.

  Checked against the generated corpus rather than argued: 32 generated sources carry a switch, every
  one listing exactly clock, nodeNameLookup and serviceRegistry.

  Residual, and stated because it is the honest edge: getNodeById's fallback previously found a
  PUBLIC NON-AUDITOR field by reflection if one was absent from nodeNameLookup. It no longer will.
  A graph node should always be in nodeNameLookup — the fallback existed for auditors — so the
  narrowing is the intent. If you can construct a graph where a node is a public field AND missing
  from nodeNameLookup, that is a real finding and I have not found one.

  A trap for the reader: EventLogManager.NODE_NAME is "eventLogger", not "eventLogManager". No
  generated file in the suite declares an eventLogger field or has an eventLogger case, so
  getLastAuditLogRecord threw NoSuchFieldException in these graphs before and throws it now.
