5. F5 — HIGH: THE EMBEDDED AUDIT MECHANISM IS RIGHT, BUT THE CANONICAL CODE IS NOT USABLE
================================================================================

The conceptual correction is valid: DataFlow.addSink is business output and
DataFlow.setAuditLogProcessor(LogRecordListener) is the audit route. The separator requirement and
level-before-listener ordering are also supported by runtime source.

The replacement snippet at docs/skills/embedded/run-embedded/SKILL.md:28-40 is not a complete Java route.
`writer.newLine()` identifies the ordinary implementation as BufferedWriter, whose write/newLine/flush
methods throw IOException. LogRecordListener.processLogRecord declares no checked exception, so the shown
lambda does not compile without an exception policy. `writer` is never created, its path/open mode and
parent-directory behaviour are unspecified, and the promised clean-close lifecycle is not installed.
If a custom unchecked writer is intended, its missing definition is itself the procedure.

Reproducible external evidence:

  javap -classpath ~/.m2/repository/com/telamin/fluxtion/fluxtion-runtime/1.0.13/\
    fluxtion-runtime-1.0.13.jar com.telamin.fluxtion.runtime.audit.LogRecordListener
  javap java.io.BufferedWriter

The first has `void processLogRecord(LogRecord)` with no throws clause; the second shows IOException on
write/newLine/flush/close. Runtime 1.0.13's JULLogRecordListener is a useful concrete comparison: its
constructor owns the file handler and processLogRecord writes `record.toString() + "\n---\n"`.

Required correction: provide a complete, compilable LogRecordListener/file lifecycle or keep the embedded
tier blocked and unpublishable, as D-X4 already requires. Verify it by building and running a disposable
embedded processor whose resulting file the analyser parses.

6. F6 — HIGH: THE REGENERATE PREFLIGHT STILL KNOWINGLY GIVES A FALSE POSITIVE
================================================================================

Moving the key check out of startup correctly closes the keyless-first-run failure. The regenerate
procedure at docs/skills/mongoose/run-mongoose-server/SKILL.md:49-68 still tells an agent to run
`check-fluxtion-key.sh` as “Check a key is resolvable”, then explains that this check can pass on
FLUXTION_API_KEY although the following build does not read it.

A canonical preflight whose success does not establish its stated precondition is not a preflight. A model
following the procedure can still receive PASS, rebuild, and fail at process-classes. The warning makes the
defect documented, not resolved.

Required correction: the generated Mongoose procedure must invoke a check owned by the actual build path,
or the Mongoose implementation must map the environment variable into the Builder and test that call.
Otherwise remove the unsound script from the canonical procedure and check only the file/property sources
the real regeneration command consumes.
