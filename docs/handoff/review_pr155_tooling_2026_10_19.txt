PR #155 FINDINGS, RANKED — ALL P2

F1 — VERIFIED — Scoring is not bound to the run's sealed oracle.
tools/m74_onboarding_runner.py:888 and :1031 (also :947).

Reproduction: created a cycle with predictions, pack, operator script and oracle; ran seal and init_run with valid
pins. Copied the synthetic recorded evidence into the run, keeping its generated config and pinned oracle digest.
Changed the observed pointer to logTime=999: the original oracle correctly yielded FAIL. Then changed the oracle to
999 after sealing. verify_seal correctly refused "oracle.json changed after the seal", but score_run accepted that
same changed oracle and returned PASS. The digest in the run's pinned oracle was different from the scored digest.
The score CLI supplies the current file hash as a label; neither it nor score_run compares that hash with the pin.

Remedy: require a valid pinned oracle and compare the scored bytes with the run's sealed oracle identity before any
verdict. Missing/mismatched seal material must refuse/VOID, never certify PASS. Make deliberate oracle corrections
explicit separate revisions with both verdicts retained. Require the mandatory seal inputs rather than silently
omitting absent ones. Do not let generic --pins data overwrite track, posture or seal-owned configuration fields.
Required regression: a real seal -> init-run -> oracle edit -> score sequence that is refused, with the unchanged
sealed-oracle control still scoring normally.

F2 — VERIFIED — Incomplete evidence can be certified complete and PASS.
tools/m74_onboarding_runner.py:902, :647 and :897.

Reproduction A: in a copy of run-t1-pass, changed session-record.meta.json total from 21 to 21000, keeping dropped=0
and sinkFailures=0 and the 21-record export. Result: complete=true, verdict=PASS. The scorer never reconciles total
with the parsed/exported count. SessionAuditSink.total() explicitly means every offered record, so this is a
detectable truncated/inconsistent export, not an unknowable absence.
Reproduction B: deleted answers.jsonl. Result: PASS with answersRead=0 and contradictions=0. Missing capture is
treated as an empty answer stream and therefore as evidence for noContradiction.

Remedy: validate required run artifacts and their schema before scoring; reconcile exported/parsed counts with the
sink metadata and validate snapshot recordSeq bounds. Distinguish a present empty stream from a missing capture.
Missing evidence must be VOID/unavailable, not a successful negative check. Required claims being informational
is intentional in SCORECARD section 3; this finding does NOT ask to make requiredFound a pass condition.
Required regressions: count mismatch and absent answer capture both void/refuse, plus valid 21-record and explicitly
empty-capture controls under an appropriate track.

F3 — VERIFIED — The person/subject boundary checks counts, not the claimed ordering.
tools/m74_onboarding_runner.py:657-673.

Reproduction: retained the operator log's increasing times, but exchanged the Start and first Send kinds. The
operator now says Send before Start; session facts still say Start before Send. Every per-kind total is unchanged.
Result: boundary.ok=true and verdict=PASS. The function docstring promises "same kind, in the same order"; the
implementation only subtracts collection lengths. It cannot establish that the matching act caused the fact.

Remedy: compare the ordered person-act/fact streams and bind request/ticket/decision identities where available;
if stronger ownership cannot be proven from current fields, report that limitation rather than boundary.ok=true.
Keep the existing missing/extra-act checks. Required regressions: reordered acts/facts with identical totals, wrong
decision/request identity, and a correctly ordered/correlated positive control.

F4 — VERIFIED — A supposedly frozen, isolated Maven seed can retain live external symlinks.
tools/m74_onboarding_runner.py:424 and :369-370.

Reproduction: made a DEMO seed jar a symlink to a harmless file outside the seed; its _remote.repositories listed
the jar under central. m2_provenance returned clean=true and seed_m2 accepted/copied it with symlinks=True.
After changing the external file, the run repository's jar bytes changed, but seedTreeSha256 still matched.
tree_sha256 hashes the link text, not the artifact bytes that Maven reads. The supposedly per-run copy still reads
outside its own repository and its recorded digest does not identify the actual dependency content.

Remedy: reject symlinks in seeds, or explicitly resolve/materialise only authorised contained content, checking
provenance and hashing the bytes actually copied. Cover directory aliases as well as artifact-file aliases.
Required regressions: external jar and directory links refused/materialised safely; changing an outside target
cannot alter an accepted run's artifact bytes while preserving the recorded seed identity; regular clean seed works.

F5 — VERIFIED — Approval accounting uses a spec-era field absent from today's Java fact.
tools/m74_onboarding_runner.py:770; tools/test_m74_onboarding_runner.py:441 (synthetic decision=ALLOW shape).
Actual contract: src/main/java/telamin/fluxtion/audit/analyser/analyser/session/SessionEvents.java:1952.

Reproduction: instantiated the real compiled LocalAgentPermissionAnswered Java record with allow=true,
by=PERSON, written=true and parsed its actual toString through the scorer. Result: granted=0 and
deniedBy={PERSON:1}. Current facts carry the boolean allow, not decision=ALLOW. The test uses an invented old
shape and therefore passes while the actual shipped shape is miscounted. The generic else also counts non-person
allows as denials.

Remedy: use today's allow/by/written contract, separate positive pre-allows from actual denials, and explicitly
account for an answer not delivered to the process. Test records emitted from the real Java type, not a hand-built
obsolete string. Refresh nearby documented unavailable/spec-only fact assumptions against the released source.
Required regressions: person allow, person deny, pre-allowed allow and written=false using current record fields.

F6 — VERIFIED CURRENT DISAGREEMENT; INFERRED FUTURE CI GAP — The mirror accepts a pack Java refuses, and CI does
not execute the authority it claims to pin.
tools/m74_onboarding_runner.py:160-163; tools/test_m74_onboarding_runner.py:29-44;
.github/workflows/ci.yml:97-98.

Reproduction input (where <NBSP> is the literal U+00A0 character, and the hash is forty 'a' characters):
  # T
  1. **X** — example: https://github.com/telaminai/diamond/archive/aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa.zip<NBSP>
Python lint_pack returned a valid example after parse_example's Python strip() removed the NBSP. The current
compiled Java PromptPack returned {line:2,cause:EXAMPLE_NOT_ARCHIVE}. Java's whitespace treatment does not remove
that character. No archive was downloaded; both parsers ran locally on the same bytes.

The existing 89 cases all agree today, and running the ACTUAL recorder on a disposable fixture copy reproduced it
byte-for-byte. However, the added CI step runs only Python tests against saved JSON Java verdicts. It does not run
the Java recorder or compare current compiled PromptPack with that JSON. A later valid Java grammar change can
leave the mirror stale without this claimed cross-check detecting the drift (INFERRED from the executed test and
the workflow; no production Java mutation was performed).

Remedy: align raw example URL/digest stripping with Java semantics and add this NBSP case to the recorded corpus.
Add a non-writing --check path and execute it against freshly compiled classes in CI; fail on drift rather than
silently regenerating the oracle. Keep explicit re-recording as the intentional maintenance operation.
Required regressions: this same-byte Java/Python disagreement is caught before the fix and agrees afterward; a
changed current Java verdict is detected by the CI check independently of the stored expected JSON.
