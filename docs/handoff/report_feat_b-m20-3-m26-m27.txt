b40f207  B-M20-3 — graph edits persist as they happen, to the active project tier
  Root cause (diagnosed against the owner's live setup, four production graphs lost):
  config.savedGraphs was only synced from the open tabs at export/exit; ProjectSession.flush()
  therefore always wrote a STALE (usually empty) graph list to the profile, while the exit path
  wrote the real graphs to the GLOBAL tier regardless of the active project; quitting with no log
  open could wipe previously saved graphs outright.
  Fix is layered so a stale flush is impossible by construction, not just unlikely:
    - GraphPanel fires an onMutation callback at every mutating site (addKeys, addExpr, remove,
      style, pin/unpin, caption, notes, axes);
    - GraphTabs aggregates panel mutations + add/rename/close into one change listener, SUPPRESSED
      during restore (restoring a profile must not echo back as an edit);
    - MainFrame: change listener -> saveConfigQuietly() + project.requestSave() (timeliness);
      ProjectSession gains a preSave hook that re-syncs tabs -> config before EVERY profile write
      (safety net); the quit sequence now syncs under guard and flushes the project session.
  GraphTierPersistenceTest (3 tests): a dispatcher-created graph reaches the ACTIVE PROFILE file
  and not the global tier; a stale config is re-synced by preSave; restore does not mark dirty.

  with full-graph edges a->b->c, routes of a = {a} alone); outsideWorld() supports boundary
