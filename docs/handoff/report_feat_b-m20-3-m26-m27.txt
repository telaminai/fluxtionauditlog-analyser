b40f207  B-M20-3 — graph edits persist as they happen, to the active project tier
  Root cause (diagnosed against the owner's live setup, four production graphs lost):
  config.savedGraphs was only synced from the open tabs at export/exit; ProjectSession.flush()
  therefore always wrote a STALE (usually empty) graph list to the profile, while the exit path
  wrote the real graphs to the GLOBAL tier regardless of the active project; quitting with no log
  open could wipe previously saved graphs outright.
  Fix is layered so a stale flush is impossible by construction, not just unlikely:
    - GraphPanel fires an onMutation callback at every mutating site (addKeys, addExpr, remove,
      style, pin/unpin, caption, notes, axes);
    - GraphTabs aggregates panel mutations + add/rename/close into one change listener, SUPPRESSED
      during restore (restoring a profile must not echo back as an edit);
    - MainFrame: change listener -> saveConfigQuietly() + project.requestSave() (timeliness);
      ProjectSession gains a preSave hook that re-syncs tabs -> config before EVERY profile write
      (safety net); the quit sequence now syncs under guard and flushes the project session.
  GraphTierPersistenceTest (now 4 tests): a dispatcher-created graph reaches the ACTIVE PROFILE
  file and not the global tier; a stale config is re-synced by preSave; restore does not mark
  dirty; quitting with NO log open cannot wipe graphs saved by an earlier session (the exact
  pre-fix data-loss path — empty tabs synced over the restored list at quit).

3. ASSUMPTIONS the reviewer should challenge
================================================================================
A1  ROUTES semantics = (transitive ancestors of the selection) ∪ (transitive descendants), each
    closure one-directional. This matches the owner's escalation description ("transitive parents
    and transitive children") and TopologyFocus.expand's original implementation. It does NOT
    include descendants-of-ancestors (a sibling fed by your parent is not on your route) — one
    reading of the old TopologyFocus javadoc ("every route in ... and everything downstream of
    it") could suggest otherwise; the javadoc reading was NOT implemented, before or now.
A2  rowAtOrBefore assumes log times are NON-DECREASING in file order — true for a single-logger
    file, the shipped read model (same assumption SeriesExtractor documents for row-order scans).
    A merged multi-logger file with interleaved clocks would binary-search wrongly; nothing new
    here relies on more than the existing graphing path already assumed, but 'at' makes the
    assumption load-bearing for a verb.
A3  read.fields splits "instanceId.key" on the LAST dot (instanceIds are Java field names and
    contain no dots; keys must not either). A key containing a dot would mis-split silently.
A4  ignoredParams is only as truthful as VerbSchemas is complete. Every verb's accepted top-level
    params were audited against its schema by hand (the audit found aggregate.limit); if a future
    verb accepts an undeclared param, the dispatcher will wrongly report it ignored. There is no
    test that can catch that automatically — the schema IS the contract.
A5  GraphTierPersistenceTest wires the change-listener/preSave contract the way MainFrame does
    rather than instantiating MainFrame (full-app Swing, headless CI). It pins the contract, not
    MainFrame's copy of the wiring — E5 below covers the live path.
A6  Per-mutation persistence (every graph edit -> saveConfigQuietly + requestSave) assumes
    ProjectSession.requestSave debounces/coalesces adequately; no debounce was added on this
    branch. If an edit storm (drag-resize style interactions) proves chatty, the listener is the
    single place to throttle.
A7  series/read/goto additions are read-only by construction; the FAQ security answer and
    FaqSecurityContractTest were deliberately NOT touched (the spec's own acceptance guardrail).
