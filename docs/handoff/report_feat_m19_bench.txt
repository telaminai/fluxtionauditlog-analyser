THE FIRST RUN FAILED ONE STEP, AND THE FAILURE WAS IN MY SLICE, NOT THE BENCH: "a fresh install started
with --rest shows no first-run dialog (it said so on stdout)". The --rest branch in the constructor SAVES
the config (to persist the transport), so by the time the splash timer called
showFirstRunSettingsIfNeeded(), configStore.exists() was true and the method returned before it ever
reached the property check. The dialog was suppressed by an accident of ordering, and the stdout note
the slice promised never printed. Fix: `firstRunAtStart` captured in the constructor BEFORE the save;
the method reads that. The bench also now polls stdout briefly — the first-run check fires from the
splash timer ~0.7 s after the window shows, which can be after the socket first answers.
Recorded because it is the bench doing its job on its first outing: the slice it was built beside
had a defect that reading the code would not have shown.
