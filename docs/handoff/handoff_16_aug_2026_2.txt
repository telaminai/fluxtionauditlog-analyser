  e) THE VERB SET IS NOW TWELVE, not eleven. `report` was added (export a finding as a PDF).
     VerbSchemasTest and McpToolsTest both assert the exact set and both had to be updated — that is
     working as designed, do not weaken those assertions.
     Also: `screenshot` and `report` are now marked destructiveHint:true. Both write a caller-supplied
     path unconditionally and can overwrite a file the app knows nothing about; `screenshot` had been
     mis-marked since it shipped.

  f) NEW PERSISTED STATE, AND A TIERING QUESTION FOR YOU. GraphSpec now carries `explanation`,
     `notes[]` and `rightAxis[]`, written through ConfigStore.writeGraphs/readGraphs. Saved graphs were
     ALREADY in the M15 shareable whitelist, so these ride along with no new boundary — but note what
     they now contain: an author's prose about a specific log. A shared setup carrying someone else's
     analysis notes is arguably a nuisance in the same way their text size is (M22.32). NOT decided.
     Flag it in your report with whatever you choose.
     >>> Findings themselves (Finding: recordIndex + note + fix) are DELIBERATELY NOT PERSISTED. They
     are keyed by model row index and cleared when a log is opened, exactly like flags — a row index
     means nothing against a different file. If M20 ever wants findings to survive, they must be
     re-anchored on something stable (byte offset), and that is a design change, not a config key.

  g) A DESIGN CONSTRAINT WORTH NOT BREAKING. A finding has exactly ONE write site — the record's flag.
     It has three readers: the note column in the records table, the callout painted on the topology,
     and the exported PDF. The `topology` verb's `callout` field is a VISIBILITY switch and carries no
     text of its own, on purpose. If a future milestone adds a second way to author the same sentence,
     the two will drift; this repo has produced disagreeing halves three times already (M22.55 being
     the most recent).

  h) NEW PACKAGE: report/ — Finding (value), PdfDoc (a small dependency-free PDF writer: colour, text,
     rects, Flate/DeviceRGB images, standard-14 fonts, TOP-LEFT coordinates flipped internally), and
     FindingReport (layout). diff/TextPdf was reimplemented on top of PdfDoc — there is ONE PDF writer
     in this codebase and it should stay that way. 14 tests in FindingReportTest.

================================================================================
CONSTRAINTS (from the spec — follow, don't re-decide)
================================================================================
- Global and project sets are DISJOINT. The API key can never be written to a profile — by
  construction, not by filtering twice.
- Switch REPLACES the project set; Import (merge) stays additive. Never conflate the two.
- No active project → behaviour is exactly today's app. The global config's project-scoped values
  remain the "no project" defaults and are restored when switching back to no project.
- Relative roots in a profile resolve against the profile file's directory (M19.2 — reuse it).
- Canonical profile path: <project>/.analyser/project.fluxtion-settings.
