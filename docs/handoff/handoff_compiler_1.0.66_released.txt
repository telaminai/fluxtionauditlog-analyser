HOW THE DEFAULT WAS VERIFIED — by comparison, not by inspection
===============================================================================

Reading 20 fluxtion.* keys out of a no-flag build proves the vocabulary is on. It
does NOT prove the mode is PARALLEL rather than AGGREGATED — both emit the same
key set. So the mode was established by generating all three explicitly against
the DEPLOYED backend and comparing:

  no-flag  vs  PARALLEL     IDENTICAL      (byte-for-byte, 16510 bytes)
  no-flag  vs  AGGREGATED   differs, 34 lines
  no-flag  vs  OFF          differs, 142 lines

The second and third rows are the point: they show the comparison can TELL THE
MODES APART, so the first row means something. A check that matched everything
would have proven nothing.

Incidental numbers you may want for fixtures:
  OFF          7,726 bytes,  0 fluxtion.* keys
  PARALLEL    16,510 bytes, 20 fluxtion.* keys
  AGGREGATED  16,769 bytes, 20 fluxtion.* keys

  descriptor fingerprint stamped: 585b1a76fd6ff5f94b8f00d95b4cb0df…

ALSO IN 1.0.66 — the ordering windows you found
===============================================================================

Fixed, and your rejection of my explanation is recorded in the code rather than
just in a tracker. You were right that "unreachable because framework nodes never
enter authoredNodes" is not what closes them: the node at risk is the AUTHOR'S,
arriving through the generation context while also named in rootNodeConfig or
their public nodes.

AuthoredNodeOrderingWindowTest drives both windows with a stubbed
GenerationContext and FAILED against the previous ordering — the evidence my
earlier claim never had. Fixed by hoisting both author registrations above the
guards, as you prescribed, so the guards cannot read a half-built set. The test is
kept as well: a structural fix that nothing exercises is one refactor from being
undone.

Your point about why NodeClassificationInvariantTest could not have caught it —
none of its five shapes uses rootNodeConfig, none puts one instance in both a
context collection and the author's public nodes — is quoted in the new test's
javadoc, because it is the transferable part.
