4. THE WORK, CONCRETELY
================================================================================
A · SELECTION. Consume `m19-skills/2`: selection = `common` + the specialisations your template declares.
    - `common` today: `load-audit-log`, `guided-start`
    - specialisations: `mongoose`, `embedded`, `spring`, `replay`
    - **never select `replay` unless the template has a real replay entry point.** Its skill carries a
      required marker you could not substitute, and v3's acceptance already refuses a surviving marker.
      This is exactly the defect C1 caught in our own draft.
    - worked example to sanity-check against: a spring+mongoose template selects
      `common/load-audit-log`, `common/guided-start`, `spring/add-a-node`,
      `mongoose/run-mongoose-server` — and **not** `common/replay-a-run`.

B · SUBSTITUTION. Markers currently needing a project-owned value:
    - `spring/add-a-node` — the exact regeneration command, and whether it needs a Fluxtion API key
    - `mongoose/run-mongoose-server` — the exact clean-stop command (pre-existing)
    - `common/replay-a-run` — only if you select it

C · THE BUNDLE'S `CLAUDE.md`. Render from `reference-set.json`:
    - ship only `agreed` entries — four today
    - `appliesTo` **selects**, it does not annotate: a `spring` link must not appear in a non-Spring
      project. An always-in-context file is a tax on every turn
    - below the links, only what the set does NOT cover: this project's paths, commands, graph — and the
      audit contract until telaminai/fluxtion#22 lands
    - **restate nothing the agreed set already carries.** That duplication is why four wrong versions of
      the audit contract got written; pointing is what makes one upstream edit improve every project
    - generate `AGENTS.md` from it; never hand-maintain a twin

D · PROFILE. Register each selected skill as `runbook.N.*` with its frontmatter description, per v3's
    table. Unchanged by v4.

4b. THE RENDERED REFERENCE BLOCK — a worked target, NOT a byte-for-byte contract
================================================================================
This is what the analyser's own `ReferenceSet.markdown("spring")` produces today, for a Spring-authored
project. Use it as a target for CONTENT. **Byte-identity is explicitly not required** — acceptance is

    # Working in this project

    **Read these first — the canonical Fluxtion authoring resources. This file does not repeat them, so
    that improving them improves every project at once.**

    - <https://fluxtion-playground.dev/build-with-ai> — How to author Fluxtion with an LLM, and the
      compile/run loop the rest of the stack serves.
    - <https://fluxtion-playground.dev/CLAUDE.md> — The author orientation, including the source-gen
      triage table that maps a build error to its fix.
    - <https://fluxtion-playground.dev/fluxtion-golden-path.md> — The blessed shape and its gotchas;
      carries the worked auditLog chaining example.
    - <https://fluxtion-playground.dev/spring-authoring/contract.md> — The FluxtionSpringConfig field
      table: nodeBeans, ignoredBeans, eventTypes and the XML shape.

    Below this line belongs only what those do **not** cover: this project's own paths, commands and
    graph.

For a NON-Spring template the fourth bullet must be **absent** — `appliesTo` selects, it does not
annotate.

**BOUNDARY — decided 2026-08-30, and this is the contract owner's call you asked for.** End the generated
block with, on its own line:

    <!-- reference-block:end -->

**Emit the marker; do NOT match a sentence.** The prose above and below it is written for a human and must
stay free to improve — the two repos had already drifted (*"Everything below…"* against *"Below this
line…"*) before anyone noticed, which is precisely what welding a parser to a sentence produces. An HTML
comment renders as nothing, says one thing, and belongs to the machine.

The bench bounds its restated-rule scan on that marker and **fails closed without it**: no marker, no
boundary, and the check refuses rather than guessing. So a generator that stops emitting it fails a check
instead of silently disabling one. The analyser's own renderer emits it too, and a test pins that every
agreed link sits *above* it.

5. DONE LOOKS LIKE — and it is executable
================================================================================
Run the analyser's own static preflight against your generated bundle:

    python3 bundle-bench.py --analyser-version <version> <unzipped-bundle-or-zip>

It already enforces v3 in full — including **no `TODO(bundle)` or `/path/to/` survives anywhere** — and it
now also checks the v4 obligations when your bundle declares `m19-bundle/4`: the agreed reference URLs
present, the `appliesTo`-gated one present only for a Spring project, no EXCLUDED resource shipped, no
restated rule, `AGENTS.md` byte-identical to `CLAUDE.md`, and no `replay-a-run` shipped with an
unsubstituted marker.

**A green run of that bench on a generated bundle is the hand-back.** v3's acceptance still applies in
full. v4 adds:
  [ ] generated `CLAUDE.md` carries every agreed URL that applies to this template, and no URL whose
      `appliesTo` does not match
  [ ] it restates no rule an agreed resource already carries
  [ ] selected skills == common + the template's declared specialisations
  [ ] a template without a replay entry point ships no `replay-a-run`
  [ ] `AGENTS.md` byte-identical to `CLAUDE.md`, generated
  [ ] **no `TODO(bundle)` survives anywhere in the generated bundle** (v3, and the gate that keeps v2
      honest)
