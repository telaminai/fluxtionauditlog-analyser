## Required corrections

### R1 — High: coverage captures the store and its identity at different instants

**Locations:** `ui/ActionExecutor.java:280`, `:290`, `:299`, `:311`.

The store is fetched first, the session snapshot later, and the topology later still on the EDT. The filter is a
live object during assessment, and its identifying snapshot is taken after assessment. Capturing the session
before scanning is insufficient: it must identify the inputs actually scanned.

**RUN, concrete failure:** the coverage worker obtains an old one-record store containing `foreignOldLog`; a
latch lets the EDT open a different two-record log before the worker fetches the session snapshot. The worker
scans the old store but stamps the new generation. The actual `SessionDriver` accepts the qualification:

```text
coverage.ok=true, result=[foreignOldLog]
current.total=2, current.generation=2
scope=first 1 of 2 records, notDeclared=[foreignOldLog], stale=true
```

The new log contains only declared `rootNode` records. The stale label claims the new log grew since that
comparison; it does not disclose that the comparison was of a different file. This is wrong evidence, not just
an obsolete reply. See [CoverageRaceProbe.java](evidence/m44-4-single-state-2026-09-24/review-probe/CoverageRaceProbe.java)
and its [output](evidence/m44-4-single-state-2026-09-24/review-probe/coverage-race-output.txt).

**Required:** capture the store, graph input, session pair identity, immutable filter and intended scan bound as
one coherent preparation, with the session's verdict applying to that tuple. Scan off the EDT, then publish only
against that tuple. Include a latch-controlled regression for this ordering, and changes of graph/filter during
preparation. The existing `aStaleComparisonIsRefused` tests a correctly stamped old result arriving late; it does
not protect incorrect stamping with the new identity.

### R2 — High: the exported coverage table bypasses the session's refusal

**Locations:** `ui/MainFrame.java:1348–1370`, versus `ui/ActionExecutor.java:290–293`.

`coverageForReport` checks presence and graph provenance and then calls `CoverageService.assess`. It does not
consult `SessionSnapshot.claim()`. Sharing arithmetic is not sharing the verdict about whether that arithmetic
is meaningful.

**RUN against the built application:** open the committed recovery graph together with a constructed log whose
only id is `foreignOnly`. Deliberate graph retention is allowed. On this exact state, the coverage action refuses:
“scoring against it would still be wrong.” A report with a coverage table exports successfully and the PDF prints:

```text
declared 3 · covered 0 · uncovered 3 · ratio 0.0 · 1 records · scope: whole log
```

The PDF also prints a membership warning; that does not make its numeric verdict agree with the refusal. See
[ReportCoverageProbe.py](evidence/m44-4-single-state-2026-09-24/review-probe/ReportCoverageProbe.py) and
[the inspected PDF text](evidence/m44-4-single-state-2026-09-24/review-probe/report-probe-output.txt).

**Required:** obtain the report's coverage permission/qualification from the same session decision and bind it
to the report's inputs. A refused comparison should render its refusal, not a usable-looking ratio. Add a
cross-surface test of action and exported artefact for this mismatch, inferred graphs and inadequate audit
capability. The frame's “does not compute” static guard passes today because it targets pairing calls/fields,
not this parallel coverage policy.

### R3 — High: a rolled set loses its members' read-through freshness protection

**Locations:** `parse/LogStore.java:154–155`, `parse/RolledLogStore.java:115–123`.

`RolledLogStore` delegates records and raw text to its member stores but inherits a null
`readThroughIdentity()`. The action guard therefore cannot see a mapped member's suspended state.

**RUN:** open two constructed files as a rolled set with the mapping threshold forced to zero. Rewrite `v: 1`
to `v: 9` in place in its first member, retaining length and advancing its modification time. A direct mapped
store reports `UNVERIFIED`, `bytesRetained=false`, “reads are suspended until the log is reopened.” The rolled
wrapper reports null and `rawText(0)` returns the changed bytes using its old merged index.

**Required:** propagate member identity verdicts through the wrapper, with a member-specific basis and aggregate
read permission. Test both mapped and retained-heap members, and a changed member that is not first. Do not imply
that default null means all adapters were checked; the SPI needs an explicit assessment boundary too. I reproduced
the built-in rolled case, not a foreign plugin. This is a missing composition of new protection, even though the
wrapper's methods themselves were not introduced by this branch.

### R4 — Medium: the published “immutable” snapshot exposes mutable qualifications

**Locations:** `session/SessionSnapshot.java:9–13`, `:27–31`; `topology/PairingQualifications.java:34` and its
public `clear` method.

**RUN:** obtain a published snapshot with a qualification, call `snapshot.qualifications().clear()`, then read
`driver.snapshot()` again. The published qualification has disappeared while the processor's qualifier still
contains it. No fact was submitted and no change notification occurred.

The node returns an independent copy, so this does not mutate the node. It does mutate the supposed immutable
published truth. A volatile reference cannot provide immutability of its object graph.

**Required:** publish an immutable qualification value/read-only representation, or defensively isolate the
accessor. Test that consumers cannot alter later reads or equality/notification behaviour. I found no existing
production caller deliberately clearing this value; this is a reproduced exposed-contract defect, not a claim
that a current button calls `clear()`.

### R5 — Medium: a refused topology request still changes the selection

**Location:** `ui/ActionExecutor.java:1290–1293`; prevalidation starts at `:1333`.

**RUN on the real executor and panel:** load the committed MarketProcessor graph, with no focus and no selection,
then request `topology {select:"rootNode", saveFocusAs:"demo"}`. The answer is `ok=false`, “nothing to save — the
full graph is not a focus; apply one first”, but selection has changed from `[]` to `[rootNode]`.

This is not the documented exception `focus:true` followed by `saveFocusAs`, which establishes valid dependent
state in the same request. This request fails its precondition after changing the view.

**Required:** include focus-save preconditions in the plan/validation of the whole operation (including the
legitimate same-call focus case), or provide genuine rollback. Add a refusal-preserves-selection assertion.
`TopologyWholeOrRefusedTest#aRefusalIsWhole` and its mutation work, but cover a different invalid parameter.

### R6 — Medium: a valid leading BOM hides a collapsed frame

**Location:** `parse/FramingScan.java:43–51`, `:60–61`.

**RUN:** prepend one UTF-8 BOM to a two-block, no-separator constructed file. The ordinary parser accepts the
file as one record. `FramingScan` does not recognize the BOM-prefixed first header, so it treats the second header
as the frame's own first header: no candidates, no framing finding. Removing only the BOM gives candidate line 6.
The probe goes through `HeapLogStore` and `ProducerDiagnostics`, not only the helper.

**Required:** account for the first physical header under the reader's supported BOM rule without stripping BOMs
indiscriminately from payload positions. Add a store-to-diagnostic regression alongside the quoted-scalar
negative controls. The new `ByteOrderMark` work on the Mongoose branch makes this an integration boundary as well.

### R7 — Medium: an oversized pending frame is silently unassessed

**Location:** `parse/ProducerDiagnostics.java:209–215`, compared with `:200–206`.

**RUN:** give the live diagnostic an empty index and a pending frame over 1,048,576 characters, with no second
header in the inspected prefix. It returns no findings. The same frame supplied as an indexed static record
correctly returns `FRAMING_NOT_ASSESSED`. `pendingUnseparated` checks `suspected()` but ignores `truncated()`.

**Required:** emit the bounded, explicitly pending `FRAMING_NOT_ASSESSED` finding, without indexing the frame.
Test both no-candidate and candidate-in-prefix cases. This directly contradicts acceptance 10 and the new
changelog's promise that a record too long to check says it was not checked.

R3–R7 are reproduced by [ReviewProbe.java](evidence/m44-4-single-state-2026-09-24/review-probe/ReviewProbe.java);
[its output](evidence/m44-4-single-state-2026-09-24/review-probe/review-probe-output.txt) preserves the results.

### R8 — Medium, documentation/echo scope: distinguish partial coverage from universal promises

**Locations:** `CHANGELOG.md:15`, `:26–30`, `:42–47`; `docs/specs/spec-evidence-integrity.md:197–200`, `:257`;
`ui/SpotlightTarget.java:269–270`.

**RUN, known gap confirmed:** a saved chart named `saved"chart` gets address `graph:"saved"chart"`; the actual
spotlight parser rejects it. The spec names this limit, while the changelog says already-saved names remain
reachable by quoted spotlight and context publishes every chart's address. Publishing an unparseable address
as usable is not an honest compatibility path.

**READ:** the first M68.4 sentence promises every request is whole/refused, but the disposition table deliberately
retains several partial-success contracts. The non-Follow identity entry sounds universal although the table is
not suspended and R3 bypasses the guard. The as-built D-E6 paragraph still says the mapped half is unbuilt;
`MappedLogStoreReadIdentityTest` and my direct mapped probe show protection exists.

**Required:** update the as-built scope and release wording, preserve the explicit exceptions, and mark a saved
quote-name address unavailable rather than publishing a working-looking invalid address. Do not silently rename
saved definitions. Whether to add an escaping grammar or a user-mediated migration is the owner's compatibility
choice; the documentation/echo must be truthful whichever choice is made. Correct the race and report promises
only after R1/R2 actually hold.

## Optional improvements

### O1 — Snapshot notification order is not stable under the documented re-entrant listener

**Location:** `session/SessionDriver.java:214–218`.

**RUN:** the first of two listeners posts a second filter fact while being notified of `first`. The second
listener receives `[second, first]` although the final published filter is `second`. The outer loop resumes
with its captured older `next`. The Javadoc explicitly permits a listener to post a fact.

Only one production snapshot listener is currently registered in MainFrame (READ), so I have not demonstrated
an existing screen ending stale this way. Before adding another, queue publications or defer posted facts until
all listeners receive the current publication, and pin monotonic delivery. The standalone probe includes this.

### O2 — Define graph revision as semantic identity, not an unexplained “exact artefact” claim

**Locations:** `session/node/OpenGraph.java:65–68`, `ui/MainFrame.java:5402–5417`.

**READ:** revision changes compare path, source, declared-id set and node-type list. They do not include graph
edges, declared authorship/audit facts or content identity. Reloading a changed graph with these four fields
unchanged preserves the revision. That may legitimately preserve an id-membership comparison, but “same graph”
is stronger if future qualifications include other graph facts. Specify which facts the revision binds and add
a same-path changed-content test before relying on it beyond membership. I did not run a full graph-reload UI
probe for this observation.

### O3 — Keep the deferred work visibly deferred

The spec's table of exceptions is useful. Apply the same precision to legacy quote-names, the still-live table,
and unassessed adapter freshness. Avoid turning a green gate for one surface into closure of the whole slice.
The older M68.1 witness runner is separate from the 101-control gate; name that boundary in handoffs rather than
calling this “every historical M68 mutation”.

## Single-state and generated-processor audit

**READ + RUN:** the frame no longer owns a second `GraphPairing` field. Session facts cover graph installation
(including reader graphs with no file), graph clearing, log close, Follow rescoping, filter changes and deliberate
graph opens while a log is pending. Context and the Project model use the session-published pairing/identity;
menu rendering is not used as the fact-observation funnel. The generated processor, however, cannot correct a
caller that stamps wrong inputs with a current identity (R1), or a report that bypasses its decision (R2).

I read the live `docs/claude.txt` framework reference as rule 6 requires, and checked the generated
`session/generated/SessionProcessor.java` against OpenLog, OpenGraph, Pairing, PairingQualifier, CoverageClaim,
LogArrival and OperationGate. Both checked-in generated Java copies are identical. Each inspected annotated
handler/trigger is represented. Relevant routes and guards were inspected, not regenerated:

- `LogOpened` reaches gate/outcome handling, OpenLog, Pairing, CoverageClaim, LogArrival and PairingQualifier.
- `LogAppended` reaches OpenLog and recomputes pairing, claim and qualification; the boundary's no-trigger
  references do not turn an append into a project transition effect.
- `GraphOpened` reaches the gate and OpenGraph, then dependent verdict nodes; openness is distinct from path.
- `MembershipCompared` reaches the qualifier, which checks generation/revision; that check works when the
  sender's tuple is coherent.
- Generated `processEvent` handles same-thread re-entrancy by queueing, and generated batch/after-event handling
  drains callbacks. Driver-level `post` queues a fact during its operation and drains after settling. The named
  `m44-post-queues-mid-operation` mutation was caught. I do not infer off-thread dispatch support: the driver
  still refuses off its designated thread, and production UI adapters marshal to it.

The 102 frame tests ran without skips; they are executable UI checks, not a claim that I manually clicked every
screen. The two built-jar harnesses test action-socket routes, not menu button presses. New report evidence is an
inspection of the generated PDF text. I did not perform a separate human visual review of every exported plot.

## Scratch integration with Mongoose audit production

**RUN, uncommitted scratch merge:** `14a72acc` plus fetched Mongoose head
`e5541d5b455ab34d16c8b93a8f459db3b917bfc3`. This is the exact integration subject I tried; neither branch was
changed. There are five conflicted files:

- `CHANGELOG.md`
- `parse/HeapLogStore.java`
- `parse/ProducerDiagnostics.java`
- `topology/CoverageService.java`
- `ui/MainFrame.java`

**READ of both sides and merge result:** these are semantic combinations, not safe “take ours” resolutions.

1. Heap identity checks must coexist with valid-prefix UTF-8 decoding, pending bytes and failed-read status.
   Preserve replacement retirement and every-byte prefix verification; do not resurrect partial-character failure
   or silently lose the producer branch's boundary accounting.
2. Producer diagnostics must retain pending-frame inspection even with zero indexed records. The other branch's
   early return and older substring framing path cannot replace FramingScan wholesale. Distinguish source bytes
   from a plugin's rendered text, including binary-source exclusions.
3. Coverage must keep a single captured row bound for the scan, filter membership and per-node level annotations.
   Mixing the branch's fixed `rows` with an array allocated from an earlier size and a later dynamic loop bound
   is unsafe under append. Preserve authored membership/ratio availability and the producer branch's annotations
   without removing annotated nodes from the denominator.
4. MainFrame must refresh diagnostics for pending growth and decode failure as well as indexed growth. Combine
   the producer diagnostic skip rule with this branch's pending-character observation; do not skip a changed
   pending frame merely because the indexed count is unchanged. Replacement must retire the session generation.
5. Cleanly merged `LogStore`/mapped/rolled changes do not prove semantic integration. Wrapper default null still
   loses member read-through identity (R3), and clean per-node annotation code still needs to be tested against
   the changed coverage population and captured scope.

I aborted the scratch merge after recording it. I did not resolve, compile or test this combined tree. Its successful integration remains unverified. Analyser
approval alone cannot approve either producer metadata or an unresolved integration.
