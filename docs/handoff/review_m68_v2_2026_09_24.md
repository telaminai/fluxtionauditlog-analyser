# Review — M68 evidence integrity, proposed v2

**Subject:** `docs/specs/spec-evidence-integrity.md` and tracker M68 at
`610d5777`, 2026-09-24. **Verdict: CONDITIONAL.**

The correction to three authored, covered nodes is right. The two fixes are distinct and a constructed log
is sufficient to exercise them. However, acceptance 2 introduces a new conflation: no coverage population
does not mean no membership comparison. D-E2 also needs to distinguish differently scoped observations,
and D-E10 needs to name the existing authority requirement, not equate a version gate with trust in a key.
Those are the first-slice corrections R1–R3 below. No new client, original session log or publication is
needed to settle them.

The later slices still have specification work: the framing predicate is not defined, despite an existing
detector that already overclaims; the whole-or-refused exception list is still empty; and D-E6 still says
what must be defined rather than supplying its replacement/append policy.

reviewer. I read G's report and checked v2 against its exact source tree, the published contract and the
committed artefacts. Agreement between earlier reviews is not used as evidence. In particular, this review

Only this review is changed. No spec, tracker, source or preserved evidence was edited. All probes below

## 2. Does the existing trust gate cover authorship?

**Structurally compatible, but not a complete trust decision. R2, Medium. Inspection.**

`GraphVocabulary.trustedForNodeFacts()` is simply `present() && major() == SUPPORTED_MAJOR`.
It accepts supported node metadata in both PARALLEL and AGGREGATED form. It takes no key argument,
validates no boolean value and checks no producer authority. Adding `framework` to its javadoc does not
provide those checks.

There is relevant prior policy that both earlier reviews failed to follow through:

- `spec-graphml-vocabulary-consumption.md`, D-V2 amendment, requires supported vocabulary **and a
  named authority for the key**. It records earlier incorrect emissions of `framework`; emission alone
  was explicitly insufficient.
- `docs/specs/completed/tracker.md`, M45.4, records that authority supplied and the analyser's verification
  on released 1.0.65. It says to unpark consumption and explicitly warns that the fact is NODE-scoped.
  This is an existing basis to cite, not evidence that the analyser already consumes the fact.

**Required before M68.1:** link that authority/verification entry; state supported version, applicable
node kinds and valid true/false handling; specify the fallback rather than instructing the implementer
to “define” it. Reuse the heuristic for legacy/absent/invalid/untrusted data only with a disclosed inferred
basis and the existing kind exclusions. Do not present that fallback as authoritative authored provenance.
I did not independently rerun the producer's 1.0.65 verification, and do not claim the existing Java gate
itself proves that verification.

The fallback need not preserve the original false *membership* warning: D-E1's full-graph membership
test must operate independently of classification even for an old graph. Legacy coverage may still
exclude this framework-class node heuristically; that is a disclosed fallback limitation, not a reason
to say its ID is absent from the graph.

Add cases for declared false overriding a framework prefix, declared true overriding an ordinary class
name, an absent key, an invalid value and an unsupported major. Preserve usable per-node facts in
AGGREGATED mode. A count matching the graph-level summary is corroboration, not a substitute for those cases.

## 4. Is the framing diagnostic sufficiently specified?

**Not yet. R4, Medium; a stronger existing defect was reproduced.**

`ProducerDiagnostics.unseparated` already scans each indexed frame for a second raw substring
`eventLogRecord:` within its first 1,048,576 characters. It then counts such substrings and says the frame
contains that many records. `MainFrame` computes these diagnostics on open, exposes them under
`context.producer`, and places a warning/tooltip on the human surface. M68.3 is not starting from an
absent diagnostic.

A constructed **one-record** input with this ordinary quoted value:

```text
eventToString: "literal eventLogRecord: text"
```

produced: “record 1 alone contains 2 records run together”. The reader still returned one record.
This reproduces exactly the overclaim v2 prohibits, without a malformed multi-record file.

**Required before M68.3:** select an observable predicate. One implementable conservative candidate is:
within one raw frame, find at least two physical record-header candidate lines whose trimmed content is
exactly `eventLogRecord:`, excluding comments and text known to lie inside quoted scalars under the active
encoding. Publish the inspected span and candidate locations as the basis. For example: “Repeated
header-looking lines inside one frame; separators may be missing. This does not establish multiple events.”
An unquoted multiline payload may still be ambiguous; retain the suspicion qualifier and raw text.
This is a proposed predicate, not one v2 already specifies or this review implemented.

Specify whether/how the scan is bounded; beyond a bound means not assessed, not clean. Keep actual record
counts and framing unchanged. Test legal single records, the quoted false-positive case, an ambiguous
unquoted payload, real collapsed input, split separators and pending tails. Under follow, pending raw
content is not yet in the index: an index-only scan can miss the entire case. Name how the pending-frame
observation is supplied without accepting the pending record.

The spec's current “repeated record-looking content suggests” gives the correct epistemic limit but not
enough to decide which of those fixtures should warn. The existing detector and its named tests should
be extended, not duplicated.

## 5. Is whole-or-refused under-enumerated?

**Yes. R5, Medium, before M68.4. Inspection, plus existing tests and two pure probes.**

I followed the sixteen action routes in `ActionDispatcher`, the relevant `ActionExecutor` branches,
source selector validation and report parsing. The following cases are absent from the explicit list:

| Combination | Existing behaviour needing disposition |
|---|---|
| `open {log, format, graphml}` | The format branch returns after opening the log; graph omitted. |
| `open {project, log}`, `{analysis, graphml}`, `{close, log}` | Intentional precedence, with ignored acts reported after the winning act. |
| `open {discover, graphml}`; log plus processor/design/diagnostics | Early-return omission or sequential effects that may partly complete. |
| `graph {name, rename, series}` | Rename returns before applying the other changes. |
| Graph with mixed valid/invalid expressions, markers, bands or external data | Deliberate partial application with warnings. |
| `report {sections:[valid,invalid]}` | Deliberately keeps valid siblings, names rejected sections. |
| `source_root {add:[valid,invalid], remove:[...]}` | Applies valid roots/removals and reports rejected additions. |
| `topology {scaffolding:false, select:missing}` | Changes the view before rejecting selection. Similar ordering applies to later invalid scope/focus. |
| Any successful action with an unknown parameter | Dispatcher decorates the successful result with `ignoredParams` after execution. |

The last is a **surface-wide** existing rule, not just one missed combination. A probe with a stub render

`ReportVerb.parse` reproduced one valid section retained beside an invalid `essay` warning.

`GraphEchoWarningsTest` explicitly protect partial success today.

`source` already restricts selector combinations, and open-follow/restore/canvas forms already require
standalone shapes. These are useful precedents, not evidence every verb is atomic. Saved-analysis steps
also deliberately retain effects before a failing step (`MainFrame.runAnalysis` reports that fact).
State whether a recalled analysis is an exception to request-wide rollback.

**Required:** populate a disposition matrix before this slice: refuse, supported transaction, or documented
per-item/sequence exception. The spec can delegate implementation auditing, but its universal rule cannot
simultaneously leave all existing exception choices unstated. Include unknown parameters and final async

## 7. Did v2 introduce another contradiction?

**Yes: R1 (High) in acceptance 2; R3 (Medium) remains in D-E2. Reproduced core cases plus inspection.**

**R1 — no eligible nodes is not no membership evidence.** Restrict the committed graph to
`serviceRegistry`, a declared framework node, and construct a log where it writes. Eligible authored
coverage has denominator zero, but graph membership is a fully established 1/1. The real `GraphPairing`
returns that match. Acceptance 2's blanket “no comparison and no ratio” would suppress an established
membership result, contradicting D-E1 and acceptance 1. A foreign ID should likewise remain reportable
when the eligible population is empty.

With no logged IDs, retention may remain permitted while membership is unknown. This is coherent only
if policy and evidence are separate. In the current code, `GraphPairing.of(graph, empty)` returns
`applies=true`; feeding it with TRACE and an installed auditor into `CoveragePolicy.decide` returns
`FULL` and claims the graph describes the log. I reproduced both calls. A prose change to `reason` alone
does not guard that downstream conclusion.

**Required before M68.1:** separate membership availability, retention policy and coverage scorable-state.
Zero denominator means no ratio, not no membership. No node observations means no pairing established,
without forcing the graph closed or allowing `FULL` through `applies=true`. If a descriptive zero-logged
count for a nonempty eligible population is retained, label it independently of execution/pairing claims.
Test the public coverage/context/report path as well as the pure comparison.

**R3 — identical answers require identical observation scopes.** `MainFrame.pairingAgainst` samples the
first 500 records; `CoverageService.assess` scans the whole log or the requested filter. A constructed
501-record log with a foreign ID only in the last record gives an all-matched sample and a whole-log
out-of-topology finding. Both observations are true at their stated scopes. I reproduced the core
comparisons; I did not drive a frame with that file.

Likewise a greater-than-half overlap can retain a graph while some IDs are absent. “Retained” and
“every observed ID declared” are not synonyms. Acceptance 2 must not accidentally change the threshold
just to make every surface say the same sentence.

**Required before M68.1:** D-E2 should require the same facts for the same graph/log revisions and
observation scope, with scope/basis disclosed. Define how a later full comparison qualifies or replaces
the sampled verdict. Accept neither an unexplained disagreement nor a requirement to make a valid sample
pretend it inspected the entire log. Add a foreign ID beyond record 500, a filtered scope and a retained
partial match to the shared-verdict acceptance.
