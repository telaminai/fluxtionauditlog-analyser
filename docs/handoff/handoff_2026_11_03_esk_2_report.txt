     SessionEvents.StreamHeadersObserved(generation, headers, records). A new log generation forgets the previous
     log's headers; a fact naming another generation is refused (staleFact). The decision is the pure
     EvidenceSetState.decide; published as SessionSnapshot.evidenceSet (new last component; the previous
     constructor kept and delegating with NONE).
   - Effect: the existing ScanLogEvidenceEffect. Its performer (MainFrame.scanLogEvidence) now posts
     StreamHeadersObserved BEFORE the findings, so the line the findings release already knows the shape.
   - Graph side: GraphOpened gains `sourceFingerprint` (the graph's fluxtion.sourceFingerprint; old arities kept);
     OpenGraph holds it and a changed fingerprint is a new revision.
   - Follow: LogContentObserved gains `streamHeaders` (count; old arity kept) and LogEvidence's content signature
     includes it, so a header appended with no record after it asks for a scan (owner answer 1).
   - FactFieldsTest inventory: StreamHeadersObserved.headers = LOG_COUNTS, GraphOpened.sourceFingerprint = DIGEST.
   - REGENERATIONS RUN: 1 (`mvn -o -Pregen process-classes`). The hosted generator reported target version 1.0.83
     (the committed processor was 1.0.79) and api 1.1.4-SNAPSHOT, so SessionProcessor.java/.graphml moved far more
     than the one node: ~5k lines. The attribution strip ran; GeneratedSourceIsPublishableTest passes.

2. Verdict rules (EvidenceSetState):
   MATCH every header states a fingerprint and each equals the graph's;
   MISMATCH a header and the graph both state one and they differ (a forced/hand-opened graph included) — a proven
     difference outranks missing evidence;
   UNVERIFIED no header, a malformed header, records before the first header, a null fingerprint on either side
     (acceptance 9: FLX-1010 now refuses the unstable key at build; a null still reads UNVERIFIED, never MISMATCH).
   Wording: "graph shape matches" / "graph shape does not match" / "graph not verified"; the reason never says
   "same build" (tests assert it). Never a refusal: nothing closes or refuses the graph (D2).

3. Pairing (acceptance 3): GraphmlDiscovery.scan(..., logFingerprint) ranks MATCH first, then UNVERIFIED, then
   MISMATCH; name fit orders within each and alone when the log states no fingerprint. Each candidate carries
   evidenceSet + both fingerprints in its map and its description. Discovery still offers and never selects
   (M35.4): "the log pairs with the matching one" = the matching build is the first offer, labelled MATCH.

  labelled MATCH. A project/bundle/manual open is judged after the fact with the status line.

  only signal is a null fingerprint, which it reads as UNVERIFIED.
