   - REGENERATIONS RUN: 1 (`mvn -o -Pregen process-classes`). The hosted generator reported target version 1.0.83

     than the one node: ~5k lines. The attribution strip ran; GeneratedSourceIsPublishableTest passes.

2. Verdict rules (EvidenceSetState):
   MATCH every header states a fingerprint and each equals the graph's;
   MISMATCH a header and the graph both state one and they differ (a forced/hand-opened graph included) — a proven
     difference outranks missing evidence;
   UNVERIFIED no header, a malformed header, records before the first header, a null fingerprint on either side
     (acceptance 9: FLX-1010 now refuses the unstable key at build; a null still reads UNVERIFIED, never MISMATCH).
   Wording: "graph shape matches" / "graph shape does not match" / "graph not verified"; the reason never says
   "same build" (tests assert it). Never a refusal: nothing closes or refuses the graph (D2).

3. Pairing (acceptance 3): GraphmlDiscovery.scan(..., logFingerprint) ranks MATCH first, then UNVERIFIED, then
   MISMATCH; name fit orders within each and alone when the log states no fingerprint. Each candidate carries
   evidenceSet + both fingerprints in its map and its description. Discovery still offers and never selects
   (M35.4): "the log pairs with the matching one" = the matching build is the first offer, labelled MATCH.

6. Segments by run key (acceptance 6, 7; owner answer 2): parse/RunSegments. Key = serverId|runId|group/name#
   generation; a new segment only when the key changes; a re-sent equal key (sink change, daily roll) continues the

   "serverId · runId(first 8) · group/name#generation". Rolled sets: RolledLogStore re-bases member headers (slice

   graph has each log's shape) and "run key: …" lines. BundleExcerpt now writes the stream header in force at the
   first chosen record and any re-sent inside the range (StreamHeader keeps its document text for this); record
   count and digests are unchanged.
