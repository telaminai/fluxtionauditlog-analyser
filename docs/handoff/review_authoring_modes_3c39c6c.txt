3 · CLAIM 3 — "silence is not a match" is the right rule, with one adoption cost
================================================================================

The claimed basis checks out: round-55/NOTES.md quotes the model excluding PricingFull for
providing "no specification of hedge inclusion" — discrimination on absence of a promise, exactly
what the resolver encodes. And the rule fails CLOSED: an undeclared variant under a profile
degrades to a visible AMBIGUOUS/UNSATISFIABLE, never a silent wrong pick — in a domain where the
notes themselves say a false alert is a reportable incident, that is the correct polarity. The
alternative (silence matches) would silently select unlabelled variants, which is the same defect
class as the five scoring bugs.

The cost the spec should state: a site profile over a LEGACY fleet (no Fluxtion-Convention fields
anywhere) is unsatisfiable by construction. Adoption therefore requires vendors to label before
customers can profile — fine as a strategy, but it is a sequencing constraint, not a free lunch.

5 · UP-FLX-47 IS WRONG, refuted by execution — and it unblocks the stated gap
================================================================================

The ask says the Spring route "offers no way to enable the audit log". It does. The audit level is
a property of the config bean the Spring file already declares:

    <bean class="com.telamin.fluxtion.builder.extern.spring.FluxtionSpringConfig">
        <property name="logLevel" value="INFO"/>
    </bean>

`FluxtionSpring.addNodes` reads it and calls `config.addEventAudit(springConfig.logLevel)` — the
wiring the round-57 workarounds tried to do by hand (raw EventLogManager bean, runtime
setAuditLogLevel), which fail for exactly the reasons observed. Executed today against released
fluxtion-builder 1.0.66: a bean file containing ONE node plus the config bean above produced a
processor whose audit listener received records on the first event. No goal parameter, no code.

Caveat: my probe ran the interpreted path; the maven goal takes the AOT path — but both share
`addNodes`, where the read happens. Recommend: re-test with this bean, then WITHDRAW or narrow
UP-FLX-47 (a legitimate residue might be "the goal's docs never mention it"). This also unblocks
round-57's stated gap — the resolver need only emit that bean and the full figure-by-figure
audit comparison can run, which is worth doing because it would give the ExpectationScorer its
first real-log execution (see §6).

6 · THE SCORER — guards are real; TWO defects found by execution
================================================================================

11/11 tests pass; G1–G5 are all implemented and each matches its named defect; G3's carry-forward
is genuinely forward-only (verified in code, not just javadoc). ScoreCommand's exit codes
distinguish untrusted(2) from fail(1), which is the right shape. But the brief asked whether the
five guards are the right five. They are five of SEVEN:

**D1 · Missing guard: event-sequence identity.** `score()` compares snapshots by index and never
compares event NAMES. Executed probe: expected [config, tick] against actual [tick, config] with
figure values arranged to coincide → "PASS 2/2 events, every figure identical". Two logs that are
semantically misaligned but equal in length score clean. This is the exact defect class G1/G2
exist for, and it errs toward agreement — the direction every historical defect erred. Fix is one
guard: `e.event().equals(a.event())` per index, hard failure like G1. No existing test covers it.

**D2 · Half-tagged node-logs silently shrink the contract.** `sawTag` fires when EITHER tag key is
present; if only one of stage/value appears (or value is non-numeric), the node-log contributes
NOTHING — and the natural-form fallback is skipped because sawTag is true. A malformed tag pair in
the EXPECTED log deletes that figure from the contract, and the comparison passes vacuously for
it. That is an err-toward-agreement path of the kind the class exists to close. (Code-read, not
probed; no test covers it.) Fix: a half-tag should be a hard failure, or at minimum fall through
to natural form.

Minor, documented here rather than filed: extra figures in `actual` are invisible by design
(probe: PASS with a rogue figure present) — defensible since expected defines the contract, but
unstated; ScoreCommand's printed figure counts partially surface it.

**And a structural observation: the scorer has never scored a real log.** All 11 tests build
synthetic snapshots; round-49's expected.txt is unreadable by its own FORMAT-NOTE; round-57's
comparison was blocked by the UP-FLX-47 belief. §5 removes that blocker. The FORMAT-NOTE's
deferral (don't repair a historical evidence artefact) is the right call — but the deferral's
cost should be paid with a NEW conforming fixture, not carried indefinitely.
