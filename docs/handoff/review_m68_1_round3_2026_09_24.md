## Required before merge

### Q5a — Two different filters erase each other (RUN)

`PairingQualifications.record` protects only a whole-log result. A filtered result simply replaces the previous
filtered one, whatever either covered.

**Reproduction:** the constructed 600-record log whose only foreign id is in record 600, opened with the recovery
graph, and **no** whole-log coverage run.

1. Filter A covers the last three records. `coverage {filtered: true}` gives `qualifiedBy.notDeclared:
   ["foreignAfter500"]`.
2. Filter B covers the first two records. `coverage {filtered: true}` gives `qualifiedBy.notDeclared: []`,
   `recordsCompared: 2`.

The finding that `foreignAfter500` is not declared, which the tool had established, is gone from `context`, and
the sampled "all 3 declared" pairing leads again. This is N2's defect with the whole log taken out: two
comparisons of which **neither** dominates, and the later one erases the earlier.

**Required:**
- keep findings from filtered comparisons that neither dominates — every distinct scope, or at least every
  undeclared id any of them found;
- or state in the reply that the earlier comparison was replaced and what it had found.

Add a test of A-then-B with disjoint filters.

### Q5b — "current filter" outlives the filter it describes (RUN)

After step 2 above, change the filter to a third range, C, and run **no** coverage. `qualifiedBy` still says
`scope: "current filter"`, `recordsCompared: 2`: the label claims the view on screen, but it describes filter B.
This is N1's defect for a filter instead of a growing log.

**Required:** record which filter a narrower comparison was made under, and mark it stale — or drop it — when the
filter changes, as N1 does for size. Add a test.

### Q2 — A stale qualification's fields still say "whole log" (RUN)

N1's staleness is honest in words.
- After a Follow append, the note says "coverage compared the first 600 of 601 records … no longer covers the
  whole log; run coverage again".
- The Topology panel leads with "first 600 of 601 records: all 3 logge…" (screenshot).
- A later coverage run replaces the stale result and finds the appended foreign id.

**But in `context.graphPairing.qualifiedBy` the structured fields still read `"scope": "whole log"` and
`"supersedesSample": true`, beside `"stale": true`.** An assistant that reads the fields rather than the note is
told the whole log was compared and the sample superseded. Q2 asks whether a stale qualification ever claims the
whole log on any surface; on `context` it does, in the fields.

**Required:** when stale, `scope` should state what was compared, as the note does, and `supersedesSample` should
be false. Assert both in `aGrownLogMakesTheWholeLogVerdictStale`.

### Q6 — The guard misses formatting inside the phrase, and its list of limits omits it (RUN)

Each plant below was made alone in a real file, then `UserVisibleWordingGuardTest` was run and the file restored
byte-identical. The addendum's plants (M23–M27) all hold. These pass the guard:

| Plant | Where | Guard |
|---|---|---|
| "…from a different" / "build than the log.", across a line break | `docs/site/support.md` | **stays green** |
| "…from a \*different\* build." | same | **stays green** |
| "…from a \<i\>different\</i\> build." | same | **stays green** |
| `"…from a different  build."` — two ordinary spaces between the words | same | **stays green** |

The docs are hard-wrapped and use Markdown emphasis and HTML throughout. The help page's original sentence was
`<i>different build</i>`, which only matched because the tag wrapped the whole phrase. So these are realistic

**The stated limits** — synonyms, strings built other than by joined literals, released history, and comments —
**do not mention any of them**, so the list is honest but incomplete.

**Required:** match against normalised text. Join a paragraph's lines, strip Markdown emphasis and HTML tags, and
collapse whitespace, including U+00A0. Add planted witnesses, or else add "formatting or line breaks between the
words" to the stated limits. The first closes the gap; the second only describes it.

### Q9 — The fourth sampling loop, and a guard that does not guard it (RUN)

`sampleLoggedIds` is used by the frame (`MainFrame.java:4189`), discovery (`:4120`) and the session's
observation (`:5279`). The session's sample **on open** is drawn by a separate loop at `MainFrame.java:3876`, for
the `LogOpened` event, which carries ids and levels. (`:5493` is the `source` verb's bounded preview, a different
purpose.)

**Witness, strict protocol:**
1. Baseline: `PairingDuringLoadFrameTest` with a display, 11 green.
2. Mutant: change the `:3876` loop to sample `PAIRING_SAMPLE - 1`. **All 11 stay green**, including
   `aSampledPairingAgreesAcrossFrameDiscoveryAndSession`.
3. Restore byte-identical; green again.

So "one method, used by all three" is true of the three it names but not of every sample the session receives,
and the parity test cannot see the fourth loop.

**Required:** route `:3876` through `sampleLoggedIds`, or narrow the claim and say why that loop is exempt.
Today the two agree; nothing would notice if they stopped.

## Optional
