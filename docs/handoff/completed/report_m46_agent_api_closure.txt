2. WHAT CHANGED
================================================================================
A3 — MainFrame (the `open {graphml}` echo; the `open {discover}` list), TopologyPanel.graphNodeCount().
  `nodes` held `authoredNodeIds().size()`. Now `graphNodes` (every node the graph declares — what the
  status bar counts) and `authoredNodes`. NO `nodes` KEY REMAINS. This is a rename of an agent-facing
  echo key, deliberately: a key that misleads is not made safe by adding a better one beside it.
  CHANGELOG ▸ Changed says what to read instead.

A4 — OpenRequest gains `launch` {NONE, COMMAND_LINE, RESTORED} and `openedBy()`; Main declares the
  startup open; `context.log.openedBy` calls `openedBy()`. The request now rides beside the operation
  in `MainFrame.pendingRequests`, keyed by opId, and the OpenLogEffect handler TAKES it instead of
  rebuilding a request from the effect's two facts — the same pattern as `pendingRolledSets` four
  lines below it ("the effect carries facts, the adapter its object"). THE SESSION PROCESSOR, ITS
  EVENTS AND ITS EFFECTS ARE UNTOUCHED — no regeneration, no change to anything the four M44.3 review
  passes covered. `takeRequest` drops entries older than the one it serves, so a refused or superseded
  request cannot accumulate.
  Scope, stated: this fixes the ATTRIBUTION. Two runs sharing a home still share a remembered log; that
  is the harness's H1 (each run its own `user.home`), which this does not change.

A5 — StepCursor.unboundLabel(recordsOpen); TopologyPanel's echo uses it when the cursor is empty and
  adds `recordsOpen`. An empty cursor's own `positionLabel()` is unchanged ("no records"), so the status
  line for a genuinely empty source reads as before.

M46.10 (found on the way) — ActionExecutor.doOpenAnalysis. The method is deliberately NOT under
  onEdt() (it waits for each asynchronous open to settle). Line 724 then called `openDecision(params)`
  on the caller's thread; that hook submits `OpenRequestReceived` to the SessionDriver, which is
  confined to the EDT (M44.3 D-A1). So every `open {analysis}` ran its steps and then failed with
  "SessionDriver is confined to the thread that created it … called on pool-1-thread-2". RELEASED in
  1.13.0, 1.13.1 and 1.13.2. The fix is one line: `onEdt(() -> openDecision(params))`.
  It was found because regenerating docs/site/sample-conversations.md (its transcript carried the old
  `nodes` key) meant re-running tools/capture-conversations.py, which aborted at scenario 4.

Docs/generated: sample-conversations.md regenerated from a real isolated run (its diff is exactly the
two intended changes: `openedBy`, and `graphNodes`/`authoredNodes` for `nodes`); five conv-*.png
regenerated by the same run; user-guide/assistant.md names the four `openedBy` values.

4. WHAT A REVIEWER SHOULD ATTACK
================================================================================
· THE KEY RENAME (A3). I removed `nodes` rather than keeping it as an alias. Defensible — the defect
  IS the key — but it is a breaking change to an agent-facing echo inside a patch-level window. If you
  think an alias for one release is the better trade, say so; it is a two-line change.
· `pendingRequests` AND THE GATE. I claim an older opId's effect can never arrive after a newer one's,
  so pruning `id < opId` is safe. That rests on my reading of the operation gate's supersede rule
  (spec-async-session-driver D-A3), not on a test. If a deferred older effect is possible, a request
  would fall back to the rebuilt two-fact form — degraded (attribution reads "you"), never wrong about
  audience or provenance, which still come from the effect. Verify the reading.
· `atStartup(restored)` IS A HUMAN AUDIENCE. A restored log still shows its dialogs to the person at
  the screen (fromActionSocket=false). With `--rest` and nobody there, a restore that hits the
  rolled-set or time-order dialog would block — PRE-EXISTING, unchanged by this block, and arguably the
  real remainder of A4. I did not change it because "a --rest launch has no human" is a policy call.
· A2 ROUTE 2 IS HELD, NOT EXPLAINED. 24 interleaved calls is a smoke test, not a proof.
· THE EDT TEST uses a java.lang.reflect.Proxy for AppControl. Check it fails without the fix (it does:
  `decidedOnEdt` is FALSE on the pre-fix line) rather than trusting that it passes with it.
