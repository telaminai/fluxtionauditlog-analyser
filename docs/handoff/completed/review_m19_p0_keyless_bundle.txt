3. REQUIRED FINDINGS
================================================================================

F1 (BLOCKING — the default bundle records nothing): the selected
mongoose-hosted-fluxtion.starter.json has performanceMonitoring.auditCapture=false. bundleSpec() changes
only analyserBundle and compileMode; mongooseConfigYaml therefore emits:

    performanceMonitoring:
      auditCapture:
        enabled: false

The generated README simultaneously says "The server captures every event cycle", and export-audit.sh
expects /api/audit/files to contain an entry. On the exact default P0 spec it will report zero files.

Required correction: the typed analyser-bundle model must force Chronicle capture enabled and autoStart
for the declared processor (or refuse generation). Add a test over generated server-config.yml asserting
enabled:true, backend:chronicle and the processor bean under autoStart. P3 then proves an event creates an
exportable file; a string assertion alone is not final evidence.

F2 (HIGH — registry data becomes shell code): export-audit.sh emits URL, AUTH_MODE and TOKEN from parsed
JSON, then imports them with:

    eval "$(python3 ... )"

A registry token or URL containing shell syntax is executed, not treated as data. Mode 600 protects the
file from other accounts; it does not make dynamic service data safe to eval, and generated automation
must not introduce a command-injection primitive.

Required correction: remove eval. Prefer doing registry parse + authenticated HTTP export inside one
small Python program, or pass NUL-delimited/argv values into shell without evaluation. Add a fixture with
spaces, quotes, dollar/semicolon characters and assert they remain data. The stop script must likewise
pass the registry path as argv rather than interpolate it inside Python source.

F3 (BLOCKING — the known false key preflight is recommended again): check-fluxtion-key.sh accepts
FLUXTION_API_KEY, while Builder 1.0.64 does not read that environment variable. The generated README now
says to check with that script before -Pgenerate-fluxtion. A user can therefore receive a successful
preflight followed by a build failure — the exact failure that M19 review F2/F3 and D-X3 corrected.

Required correction: make the bundle regeneration path check only sources the build consumes (canonical
apiKey file and an explicit -Dfluxtion.apiKey supplied to Maven), or have a wrapper deliberately map an
environment value into that system property and test the real Maven invocation. Do not document the
environment as effective merely because the shell can see it. Keep key mention confined to regeneration.

F4 (MEDIUM — bundle invariants are optional input conventions, not validation): analyserBundle is an
optional shared/importable boolean, but validate() does not require AOT, Mongoose hosting, webAdmin or
performance monitoring. analyserBundleScriptsWanted checks only the flag + webAdmin, and its README block
unconditionally claims keyless operation. An imported interpreted-mode spec can therefore validate and
ship a false keyless README. Separately:

    { serverName: spec.artifact, environment: 'dev', ...config }

allows existing service config to override both supposedly deterministic fields.

Required correction: validate/refuse every unsupported combination and derive the two identity fields
after user config (or refuse conflicts). Pin invalid interpreted/no-webAdmin/no-capture fixtures and a
conflicting serverName/environment fixture. P1's typed bundle constructor can make the valid path easy,
but validate remains the boundary for imported/shared input.

F5 (LOW, safe-stop follow-up): stop-server.sh trusts a possibly stale registry PID. Its own comment says
a crash leaves the file; after PID reuse, kill -0 can succeed for an unrelated process and the script
sends SIGTERM. Before P3 calls this a safe project stop, add a live server-identity check or another
process-owned guard and fail closed on a stale/mismatched entry. This is separate from clean shutdown
removing the registry file, which the Mongoose branch already fixed.
