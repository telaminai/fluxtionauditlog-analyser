WHAT THIS NOTE GOT WRONG

1 · It stated that `fluxtion.generatedAt` is emitted. It is not, and the reason matters: a wall-clock
value makes an unchanged graph differ on every build, which defeats the byte-stable output the same
vocabulary requires elsewhere. The key was removed deliberately. If a creation time is ever wanted it
belongs in a build manifest or sidecar, not in the deterministic graph document.

I asserted this from a stale reading and did not notice that my own check had printed nothing for
that key. The absence was the answer.

2 · It claimed the fingerprint could proceed independently of the model-authority gate, on the
grounds that it is computed from the model rather than from the relationship carrier. That is wrong
in a way worth keeping: hashing values the exporter derived by its own reflection would place a
second source of truth inside the artefact whose entire purpose is to detect drift. The digest must
be computed from the authoritative graph description, which means it follows the gate.

The note was also incomplete on carriers. A digest present only in GraphML identifies the graph and
proves nothing about a separate log. The current spec fixes four carriers for one value — GraphML,
`DescriptorSupport.Meta`, the generated-source header used by `FLX-1021`, and the audit-log header —
and the last requires a coordinated runtime change before graph/log pairing can be claimed.

WHAT SURVIVES

Only the argument for why the fingerprint is worth its size: it is the one artefact that answers "is
this the build that produced this log" without a running processor, and in a loop where a model
regenerates repeatedly, the likeliest silent failure is reasoning confidently over the previous
build's graph. That argument is already carried by the current spec, which also has the sequencing
and the carriers right. Read that instead.

The historical record of the two-implementation collision — `9402fe7` reverted, `dd36bc5` cherry-
picked as `7e63cbc`, one exporter path, one key name, one toggle — is in the compiler's tracker under
its own disposition and in git history. It does not need to live here.
