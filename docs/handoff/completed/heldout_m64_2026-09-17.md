# Held-out acceptance — M64 spotlight, a context-free client (2026-09-17, analyser 1.14.1)

**What was run.** `tools/heldout-client.py`: an LLM (claude-sonnet-5, the owner's key, local only) handed exactly
what an MCP client is handed — the bridge's server instructions and the fifteen tools from `/manifest` — and
nothing else. The demo series log and the demo graph were open. Each of the six "Ask it to show you" sentences
from the user guide ran in a fresh conversation; then the guided-start tour with the skill text attached. Two
variants: **B** with the server instructions (the spotlight guidance included — what every MCP client gets) and
**A** with the guidance paragraph removed (harder than any real client).

## Result: the claim holds

| # | sentence | B (instructions) | A (no guidance) |
|---|---|---|---|
| 1 | *Show me where the spread first crossed 0.004 — point at it.* | lit `records:row:0` + the graph tab, and said the spread is above 0.004 from the first record (true of the demo data) | same |
| 2 | *Which node never logged? Highlight it on the graph.* | `coverage` → `topology` → lit `topology:node:spreadCalculator` with a true caption | same |
| 3 | *Walk me through this cycle and highlight each step.* | lit the nodes step by step — see note 1 | ONE call, four numbered targets: the row, then the three nodes in dispatch order |
| 4 | *Highlight everything involved in that breach.* | found the breach at record 28, lit the four nodes involved, numbered | (turn cap in pass 1; not re-run) |
| 5 | *Point at the note on the chart you mean.* | asked which note — it had no antecedent (right) | lit the graph tab and asked |
| 6 | *Clear the highlights.* | `spotlight {clear}` | same |

**Tour** (skill text attached): `context` → `topology` → `goto` → **spotlight** (`detail`) → `coverage` →
**spotlight** (`topology:node:spreadCalculator`, "declared, and silent in this run") → `read` → `series` →
`goto` → `flag` → **spotlight** (`records:row:15`, "the crossing — flagged so you can come back"). Every beat lit
before it spoke, and the flag was placed. Its two `screenshot` calls were refused because the isolated home had
no exchange directory — a harness setting, not the product.

## What it showed that the tests could not

1. **Sequential single-target calls REPLACE the set.** In variant B, sentence 3 narrated step by step with one
   `spotlight {target}` per step, so step 1 went out when step 2 was lit; only the last node was lit at the end.
   Variant A did it right in one call with `targets`. The tool description says several targets go in one call;
   it does not say that a call without `add: true` replaces what is lit. One sentence in the schema description
   ("to keep what is lit and add to it, send `add: true`") — tracker M64.12.
2. **The user guide's first sentence does not fit the demo data.** `quotePublisher.spread` sits near 0.02 for the
   whole demo log, so "first crossed 0.004" has no crossing; both variants said so honestly and pointed at
   record 0. The docs example should name a threshold the demo log crosses (`riskMonitor.liveOrders` above 1 at
   record 15 is the one the point-at-the-fault skill uses) — tracker M64.12.
3. Sentences 4 and 5 assume a conversation that already found a breach or placed a note; context-free, the client
   either searched (4) or asked (5). Both are the right behaviour; the docs table's promises hold within the
   conversation they describe.

**Not shown:** a person watching. The transcripts are the client's own tool calls against the live analyser; the
screen state was read back through `context`, not looked at.
