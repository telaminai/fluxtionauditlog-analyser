2. FINDINGS
================================================================================
P1 · **AN AGENT CANNOT REACH THE UNBOUNDED ANSWER, AND IS TOLD TO CLICK A CHECKBOX.** — blocking
     `topology {scope: "routes"}` reaches `TopologyPanel.setScope` → `applyView` → `scopedIds()` →
     `routesInWorld(selection, boundRoutesBox.isSelected())`, and the box defaults to ON. So:

       (a) a SILENT BEHAVIOUR CHANGE at the socket — an agent that used to get all routes now gets
           three hops on any large graph, with no version marker; and
       (b) the echo's own remedy is unactionable for its reader. `scopeNote` says the unbounded answer
           is "one untick away ('≤3 hops' in the Topology toolbar)" — a Swing checkbox, over REST.

     This is the species this repo keeps rediscovering and naming: M35.7, and review_feat_m35_project
     N2, both "a remedy only a human at the keyboard can perform, offered to a process". The echo is
     commendably honest that the answer was bounded; it just cannot be acted on. The verb surface is
     the only way out and it has no lever.

     ON THE BRIEF'S FREEZE: the brief froze `scope: node|neighbours|routes|all`, and the report is
     right to have refused a fifth scope value. That freeze is not in tension with the fix — an
     OPTIONAL SIBLING parameter on the same verb (`routeBound: false`, or `hops: <n>`) leaves the
     scope enum exactly as published. Suggested: wire it to the same `allowBound` argument that
     already exists, default it to the checkbox's value so the UI and the socket agree, and change
     `scopeNote` to name the parameter rather than the toolbar.

P2 · **`lastRoutes` GOES STALE WHEN THE SELECTION EMPTIES, AND ONLY THE ECHO REPORTS IT.** — blocking, one line
     `applyView` short-circuits: `scoped = selection.isEmpty() ? null : scopedIds()`. `scopedIds()` is
     the only writer of `lastRoutes`, so clearing the selection leaves the previous bounded value in
     place. `updateScopeLabel` happens to be safe (it returns early on an empty selection), but the
     `topology` echo (~line 1215) has no such guard, so it will emit

         "selected": [],  "scopeBounded": 3,  "scopeNote": "'routes' was bounded to 3 hops …"

     describing a bound for a selection that no longer exists. Same class as the defect the branch
     itself fixes — a data surface saying more than is true — and the same audience reads it. Fix:
     clear `lastRoutes` when the selection empties, or guard the echo on `!selection.isEmpty()`.

P3 · **THE CAPTURE HARNESS'S SOURCE ROOT CONTAINS AN EMPLOYER EMAIL, AND ONE SHOT RENDERS THAT FILE.** — owner's call, now urgent
     Not introduced here, but this branch is the reason it matters: `capture-docs.py` adds
     `examples/fixture-generator/src/main/java` as a source root (line 306), and
     `DemoQuoteProcessor.java` line 2 reads

         Copyright: © 2025.  <a personal address on the fourth sweep term's domain> - All Rights Reserved

     inside a block that also declares the file confidential and not to be distributed — in a public
     repo. `source-navigation.png` renders exactly that file in the Source pane. THIS RUN IS SAFE: the
     pane happens to be scrolled past the header, and I read the image to confirm. Nothing pins the
     scroll position, so any future regeneration can publish it, and **rule 1's standing sweep lists
     three strings and does not include this one** — the sweep would stay green.

     M36 slice 1 already strips this header from the copies bundled into the jar and has a test
     guarding them. Doing the same to the four `examples/` files closes this permanently and makes the
     capture harness safe by construction rather than by scroll position. It is item (b) of the three
     rule-1 decisions already sitting with the owner (report_feat_m36_start_page §2).

P4 · **H6 GUARDS ON THE WRONG CONDITION.** — minor
     `if (all.size() > REPORT_WHOLE_GRAPH_MAX && !touched.isEmpty())`. What the branch actually needs
     is that `touched ∩ all` is non-empty: `shown` is built by intersecting the neighbourhood with
     `all`, so if every touched node is filtered out of `all` (all-scaffolding cycle with scaffolding
     hidden), `shown` becomes neighbours WITHOUT the path, under a caption promising "the cycle's
     nodes and their immediate neighbours". Test 3 covers `touched.isEmpty()` and not this. Corner
     case; one condition change, or an explicit fallback to the estate when the intersection is empty.

P5 · **TWO NITS.**
     (a) `fitNodeWidthToLabels()` measures `simpleName()` and `id()` only. If anything else is drawn
         inside the box at label size (an ordinal badge), it is not in the fit.
     (b) It returns the chosen width "so a caller can say whether anything changed" — no caller does.

P6 · **THE SWEEP AS WRITTEN CANNOT PASS, AND EVERYONE IS QUIETLY EXEMPTING THE SAME TWO FILES.** — owner
     Rule 1 says the sweep "must be empty". Run literally against tracked files it is not, and cannot
     be: CLAUDE.md states the rule (4 hits) and ONBOARDING.md restates it (1). Removing those means
     deleting the rule's own text. So the working definition in use is "empty apart from the two files
     that define the rule" — an unwritten exemption both sessions have been applying silently and
     phrasing as "sweep clean".

     I say this having got it wrong twice in two days. On the M36 release check I ran the sweep, saw
     the hits, filtered them with `grep -v` and reported "clean"; the second session's review of that
     branch found the sweep genuinely red for a DIFFERENT reason (prose and a test literal spelling the
     terms) and had to fix it as a release blocker. And the first draft of THIS review reintroduced the
     same defect in its own §2 P3 — corrected before this commit. A gate whose pass condition is
     unstated gets a different answer from every person who runs it.

     Worth one sentence in rule 1 naming the exemption, so "sweep clean" means one thing. The
     mechanical form that has no exemption is the one main now uses in DemoAssetsTest: read the terms
     from CLAUDE.md at runtime and never spell them anywhere else.
