================================================================================
2. WHAT THREADING THE REQUEST FOUND — the fifth and sixth instances
================================================================================
Following every path that reaches onLoaded and asking "where does this one learn who asked?":
  5 · open {logs: [...]} (the M30 rolled-set verb) called openRolledSet directly and NEVER set the
      socket flag. Its time-order modal — rolled sets are where violations happen — fired on every
      agent-driven set open. Nobody had driven that path from the socket with a bad set.
  6 · open {log} on one MEMBER of a rolled set: openFile's "Open the whole set?" confirm is a modal
      BEFORE the load even starts. M35.7 fixed the offer after the load; this one sat in front of it.
      Now: on the socket path the set is recorded as `context.rolledSetOffer` {files, note} and the
      single file opens; the agent decides with open {logs}. Cleared with the log and on the next open.
Neither needed a new mechanism: once every entry point had to state who asked, the two that could
not were the two that were wrong. That is the argument for the refactor over a fifth local.

================================================================================
3. WHAT DID NOT CHANGE, deliberately
================================================================================
  · pendingProjectOffer, declinedSourceGraph, logProvenance stay as FIELDS. They describe the LOG
    that is open (its offer, its source's declined graph, its declared origin), not the request;
    they clear in closeLog. The record's javadoc draws that line so nobody moves them into it.
  · The human path shows every dialog it showed before: rolled-set confirm, project offer,
    time-order report. HUMAN is the default for every non-verb entry point.
  · The follow-rotation reload uses reload(logProvenance): same log, same system — replacing the
    `pendingProvenance = logProvenance` hack with an explicit statement.
