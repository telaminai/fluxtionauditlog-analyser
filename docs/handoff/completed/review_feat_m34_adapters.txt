3. FINDINGS — all fixed here
  F1 · A reader's graph outlived its log and outranked the next log's own.
      closeLog() left a READER_* graph loaded ("No log open · graph supplied by the source …
      still loaded" — describing a log that is gone), and on the next log-open repairLoadedGraph()
      JUDGED it like an opened graph: whenever two systems are similar enough to pass the 0.5
      pairing, log B was read through log A's structure and — because READER_DECLARED.replacedBy
      (READER_*) is false — log B's OWN source graph could never take the slot. The rule in
      GraphSource is about the slot WHILE a log is open; nothing said a reader's graph is that
      log's DERIVED state.
      FIX: TopologyPanel.clearSourceGraph() (clears READER_*, leaves OPENED); called in closeLog()
      and in onLoaded() BEFORE repairLoadedGraph — a previous log's reader graph is residue, not
      intent, so it is not judged, it is cleared, and the status says so. GraphSource javadoc now
      carries the lifecycle sentence. Only an OPENED graph is judged and kept (M35.3, unchanged).
      LIVE: S2.1 close run.probe → graph gone (S2.2/S2.3). S4 run.iprobe (INFERRED) then run.probe
      (DECLARED) → READER_DECLARED, i.e. the NEW log's graph — before the fix it stayed INFERRED.
  F2 · The reader's failure reason was recorded and never shown.
      SpiLogStore.graphNote() is set when graph() throws — the report says "so the source does not
      look like one that simply had no graph" — but the method exists only on SpiLogStore, MainFrame
      holds a LogStore, and nothing called it. Loud degradation promised, silent in practice.
      FIX: LogStore.sourceGraphNote() (default null; SpiLogStore overrides); offerSourceGraph()
      appends "⚠ <note>" to the status; context.graphPairing carries sourceGraphNote. A third probe
      (BrokenProbeReader, .bprobe, graph() throws) is added to tools/spikes/m34-probe so the path
      has a source to drive against.  LIVE: S6.3 — sourceGraphNote names "workflow registry
      unreachable (probe)", graph NONE, log open with 3 records.
  F3 · The "ARRIVAL ORDER, NOT DISPATCH ORDER" part outlived its source.
      setOrderMeaningful(false) is set on load and reset by nothing; close a PARTIAL log and the
      Topology status keeps warning about a source that is no longer open (my own M35 F2, one field
      over). FIX: closeLog() resets it to true.  LIVE: S2 — no orderCaveat after close.
  F4 · A dangling edge from an adapter reached the adjacency maps.
      ProcessorTopology.of() dedups nodes but passed every edge through; LayeredLayout skips an
      edge whose endpoint is unknown (I first wrote "NPE on first paint" — WRONG, checked and
      corrected), but the children/parents maps the focus scopes walk would carry an id node()
      cannot resolve. GraphMlParser already skips such edges for hand-written files. FIX: of()
      drops edges with an undeclared endpoint. Test added (SourceGraphTest).
  F5 · "kept, you opened it deliberately" said of a graph nobody opened.
      judgeOpenedGraph()'s non-fit wording is M35.3's, written when every graph was opened. A
      source-supplied graph that does not fit its own log now reads "kept, the source supplied it
      with this log". Wording only; the keep is right (it is the source's own claim).
  Cosmetic, fixed: ProcessorTopology's "A topology with nothing in it" javadoc was orphaned above
  of() (re-homed on empty()); TopologyPanel's setPairingNote javadoc was above setOrderMeaningful
  (both re-homed); InferredProbeReader's javadoc said DECLARED; the report's STATUS header still
  said "slice 3 NOT started · 785 tests" over sections describing slice 3 done (header updated,
  nothing else in the report touched).
