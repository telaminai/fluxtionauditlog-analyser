Claims verified in code (the reachable half of the ledger's manual list):

  · Cancel writes no profile: `if (selection == null) return;` sits BEFORE `project.create(file)`
    in chooseAndCreateProject — cancelling the offer aborts creation entirely, which is stronger
    than the ledger sentence and correct.
  · Nothing preselected: every JCheckBox/JRadioButton is constructed setSelected(false), and the
    test asserts structurally that the dialog source contains no setSelected(true).
  · Finding is not adding: apply() only admits paths that were BOTH offered and selected
    (`offeredRoots.contains(normalized)`), re-applies the Runbooks.refuse gates at adoption time,
    skips already-declared skills, and uses putIfAbsent so a duplicate skill name never replaces
    an earlier choice. The D-AI5 test (empty selection → untouched AppConfig) pins it.
  · Empty directory → empty offer, never an error; OK on the empty offer still creates a usable
    empty profile (Selection.empty() → apply is a no-op → create proceeds).
  · The confirmed graph is a UI open only (topologyPanel.load), not a profile write — consistent
    with the graph-adoption rules elsewhere; roots/skills persist through the single
    onProfileEdited() funnel.
  · Truncated discovery is stated in the dialog ("safety cap; this is a partial offer") — the
    no-silent-caps rule holds.

F1 (MEDIUM follow-up — the entry's own challenge, answered with a concrete miss): GraphML is
discovered ONLY under the OFFERED source roots (`GraphmlDiscovery.scan(sourceRoots…)`). Three
realistic homes escape that net: src/main/resources (not a source root), target/generated-sources
(not matched by the detector — see F2), and a .graphml at the project root "beside your log",
which is R7's own motivating phrase. Consequence worth checking when the bundle exists: if the
M19 bundle's declared GraphML path is not under a detected source root, day-two discovery on a
bundle-shaped project will offer its skills and roots but MISS its graph. Suggested follow-up:
one extra bounded scan level at the chosen root (the same safety-cap style), or align the bundle
contract's GraphML path with a detectable location and record that constraint in the contract.

F2 (LOW, recorded as accepted-for-v1): detectSourceRoots reaches the chosen dir, dir/src/main/java,
and one level of children's src/main/java — nested modules (a/b/src/main/java) and generated-source
roots are missed. Reusing the shipped detector is the right v1 call (consistency over a new
walker); the step-2 context-free measurement is the mechanism that should decide whether deeper
walking is actually needed, so no change requested now.

Minor note, no change requested: the dialog's fixed 720px preferred width may clip on narrow
screens; the ledger's readability check at narrow sizes stays on the human list.

Still requiring a human at a screen: dialog readability, click-through of select/cancel/confirm,
roots/skills surviving an app restart, and the multi-module visual walk — unchanged from the
ledger entry's list minus what §3 verified in code.
