1. THE A4 CORRECTION IS RIGHT, AND MY ORIGINAL CLAIM WAS WRONG
================================================================================
I wrote that a starter shipping a skill-shaped file would have it "surfaced in the analyser's Project
panel and in `context.runbooks[]` with no work on either side."

**That is false**, and it contradicts the very decision the feature is built on. Verified in code:
`PointerDialog.discoverSkills` routes every candidate through `addRunbook(...)`, and there is exactly ONE
write site — `config.runbooks.put(...)` at line 195 — which sits behind `confirm(...)`. Discovery OFFERS;
a person chooses and confirms; only then is anything stored or served.

So M35.4's rule held in the code while I overclaimed against it in prose — the same shape as mapping
D-AI9's "no red" onto a brick foreground. Writing the decision down does not stop you contradicting it
one document later. The resolution's wording — *"discovers and offers that file; a person must still
choose and add the runbook before it is stored in a project profile or appears in context.runbooks[]"* —
is exactly right.

Checked the premise underneath it too, since a corrected claim is still worth being true: the candidate
`.claude/skills/mongoose-local/SKILL.md` IS discovered by the shipped code, named `mongoose-local` from
its frontmatter, with its description read. So the convention is adopted correctly; only the automatic
part was wrong.

2. VAL-12 IS SCOPED MORE SHARPLY THAN MY A1 WAS
================================================================================
My A1 said: make the real starter satisfy `mongoose-stub.py`'s contract, run `loop-bench.py` unstubbed,
and let it back Gates V2–V3.

The second half of that was too generous, and the resolution catches it. `loop-bench` exercises the
**loop contract** — registry glob, export endpoints, GraphML, driving the analyser. The stub serves those
exports from the in-tree demo set, so a green bench says nothing about whether **Mongoose's own audit
output** opens in the analyser. That is a different claim and it belongs to VAL-05, which still
independently requires the exact configuration, artifact path/format, fixture identity and a restart-safe
opening procedure.

VAL-12 now reads as loop conformance with "the registry/export/GraphML evidence retained", and V3 keeps
its native-audit obligation. Conflating the two would have let a passing bench stand in for the one thing
the exercise exists to establish. Correct narrowing; I would not have caught it.
