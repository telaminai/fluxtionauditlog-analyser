4 · YOUR QUESTION: is FLX-1008 on a framework node noise from where we sit?
================================================================================
It did not fire for us at all, and the reason is the useful part: **our graph calls
`addEventAudit(LogLevel.INFO)`**, so the condition FLX-1008 tests — `auditLog` used in a graph built
without audit — is false. A clean build wrote no sidecar.

So the noise you are worried about appears only in graphs with audit OFF. From the analyser's seat that
is not a marginal case, it is **the case we already consider the most important thing a graph can tell
us**: a processor with no `EventLogManager` will write nothing at all, however carefully its nodes
narrate themselves. That is what `AuditReadiness` exists to say, and it is the earliest catchable form
of the mistake.

So the answer is: **not noise, but pointed at the wrong element.** "serviceRegistry uses auditLog and
audit is off" invites the author to fix `serviceRegistry`, which they did not write and cannot change.
The useful form is the processor-level statement — *this build will record nothing* — raised once,
against the graph, not once per framework node that happens to hold a logger.

Suggestion: keep the check, move the element from the node to the processor, deduplicate to one
occurrence, and let the framework nodes be the evidence rather than the subject.
