THE MEASUREMENT THAT STARTED THIS
  `coverage` on the shipped demo — the fixture on the docs site — reports:

      declared 10 · covered 5 · uncovered 5 · ratio 0.5

  and names the five it calls uncovered:

      QuoteControl          com.acme.demo.api.QuoteControl          an EXPORTED SERVICE interface
      spreadCalculator      Nodes$SpreadCalculator                  a node deliberately not an EventLogNode
      RiskBreachEvent       Events$RiskBreachEvent                  an EVENT class
      OrderUpdateEvent      Events$OrderUpdateEvent                 an EVENT class
      MarketDataEvent       Events$MarketDataEvent                  an EVENT class

  **Every one of them can never write audit output.** Three are event classes — data entering the
  graph, not code that runs. One is a service interface. One is a node the fixture makes silent on
  purpose, and documents as such. So "50% coverage" is really "100% of what can log, logged", and the
  tool is wrong in the ALARMING direction about its own showcase fixture — on the number a support
  engineer would act on first.

  `NodeCoverage` already models the distinction: it takes `neverLogs` and reports `silentByDesign`.
  Both call sites pass `Set.of()`. The receptacle has been there since the feature shipped and nothing
  has ever filled it.

WHY THIS IS NOT A COSMETIC FIX
  Coverage's whole value is that an absence is evidence (M34.2 refuses to answer against an inferred
  graph rather than print a comfortable 100%). A denominator containing things that could never appear
  makes the number mean nothing in the other direction — and the failure is silent, because 50% looks
  like a finding rather than an artefact.

TASK — one slice per commit, suite green before each
  1  DENOMINATOR BY KIND — the cheap, evidence-free half. `ProcessorTopology.Node.kind()` already
     distinguishes EVENT and EXPORT_SERVICE from NODE/EVENT_HANDLER. An event class in a "which nodes
     never ran" answer is a CATEGORY ERROR, not a low score. Exclude by kind, and REPORT what was
     excluded and why — a denominator that quietly shrinks is its own dishonesty.
  2  SILENT BY CONSTRUCTION — the node that is a node and still cannot log (SpreadCalculator). Evidence
     is the class: no audit logger, no `auditLog` call. Needs source resolution, so it carries a third
     state: when there is no source, the answer is UNKNOWN and the node stays counted — never assumed
     silent, which would inflate the score the other way.
  3  Surfaces: the `coverage` echo, the Topology tab's coverage view, and the docs that quote the
     demo's numbers (they will change).

DELIBERATELY NOT IN THIS SLICE
  · Changing what `declared` means for a source the reader supplied (M34.1 INFERRED graphs already
    refuse coverage entirely).
  · The audit LEVEL (M40.3) — still unmeasured, still not to be claimed.

TESTING
  Pure: NodeCoverage over synthetic kind sets. The REAL demo fixture is the acceptance case — after
  slice 1 its uncovered list must contain only `spreadCalculator`, and after slice 2, nothing.

REVIEWER, PLEASE CHECK
  · That nothing is excluded from the denominator SILENTLY — every exclusion must be counted and named.
  · That a node with no resolvable source is still counted (the unknown case must not flatter the score).
  · The demo numbers in the docs, which this slice changes.
