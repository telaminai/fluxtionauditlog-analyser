RESOLUTION
----------
A1 — ACCEPTED, with an important evidence boundary. `tools/bench/loop-bench.py` is now named as VAL-12:
when Mongoose publishes the proposed registry and export endpoints, the real starter must pass the bench
without `--stub`. The current starter has neither, so it makes no unstubbed-pass claim. The bench proves
registry → export → GraphML → analyser drive; it cannot prove the starter wrote M19's local INFO text/YAML
audit artifact or that the artifact answered the predeclared question. Native V3 evidence stays required.

A2 — ACCEPTED. The candidate skill is registry-first when a Mongoose-published
`~/.mongoose/servers/<name>` exists, with an explicit YAML fallback for a single local project. It never
creates, repairs or infers a registry entry. That is UP-MNG-01's server-side responsibility.

A3 — ACCEPTED AS A TRACKED DECISION, not decided by this documentation change. UP-MNG-01 remains required
even if local scripts/skills cover the starter's operations. UP-MNG-02 remains an independent Mongoose
owner decision: retain, defer or withdraw must be recorded expressly after workflow evidence. The optional
analyser-client MCP check in V4 is not evidence for that choice.

A4 — ACCEPTED WITH A CORRECTION TO THE REVIEW'S IMPLICATION. A project-local
`.claude/skills/mongoose-local/SKILL.md` now uses `name`/`description` frontmatter and contains only a
safe, gated working agreement. It is not a graduated shared skill. Reading the M43 implementation showed
that **Find skills… offers candidates and never selects them**: a person must explicitly add the file as a
runbook before it is stored in a project profile or appears in `context.runbooks[]`. The previous wording
that this happens automatically was too strong.
