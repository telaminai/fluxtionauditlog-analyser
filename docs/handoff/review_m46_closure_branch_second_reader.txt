A2 — P4, nit: requestClose conflates "never built" with "dispatching".
  src/main/java/telamin/fluxtion/audit/analyser/analyser/ui/MainFrame.java:~4079
  `if (driver == null || driver.isDispatching()) return null;  // never built: nothing can be pending` — the
  comment explains only the first half. A close requested while the driver is dispatching (i.e. from inside an
  effect) is silently dropped, and the caller cannot tell "nothing was pending" from "your request was not
  submitted". Today no caller runs inside dispatch (the three File-menu listeners at 1576–1586 and the three
  socket verbs at 4484–4495 are all EDT-outside-dispatch), so it is unreachable; but the next caller from an
  effect would get a silent no-op. Either throw ProtocolViolation as the driver does, or split the comment.

A3 — P4, narrowing the human check for the overlay (pieces 4/5):
  Because the glass pane swallows the press, "the dismissing click does not also activate the underlying control"
  holds by construction and need not be checked by hand. What a person should still check is Escape when keyboard
  focus is in a component that consumes Escape itself (a combo box with its popup open, the search field's
  history popup): WHEN_IN_FOCUSED_WINDOW bindings lose to a focused component's own binding. One try each.
