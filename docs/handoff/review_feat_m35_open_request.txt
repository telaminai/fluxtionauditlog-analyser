2. THE REFACTOR IS COMPLETE, AND STRUCTURALLY SO
`openFromActionSocket` and `pendingProvenance` are GONE — grep returns 0. That matters more than it
reads: with the fields deleted, a path that failed to supply an OpenRequest does not compile. The
refactor cannot be half-done, which is exactly the property the three-symptom history asked for.
R1 (two loads crossing a mutable field) is gone with the field rather than guarded around.

And asking every path "where does this one learn who asked?" found two that could not answer — the
fifth and sixth modals in this family:
  · `open {logs}` never set the socket flag, so its time-order dialog fired on every agent set-open
  · `open {log}` on a rolled-set MEMBER stopped at "open the whole set?" BEFORE the load
Both are data now, and the second is the better fix: the offer becomes `context.rolledSetOffer` and
the set is one `open {logs}` away, so the agent decides instead of being asked. That is the M35.7
shape applied without being told to.

────────────────────────────────────────────────────────────────────────────────
3. FINDING — F1: A FOLLOW ROTATION THROWS AWAY WHO ASKED
`OpenRequest.reload(provenance)` returned `new OpenRequest(false, provenance)` — human-context by
construction — and the follow rotation used it:

    openFile(Path.of(followPath), OpenRequest.reload(logProvenance));   // same log, same system

`onLoaded` reads `request.fromActionSocket()` into `loadFromSocket`, which gates the time-order
dialog, `maybeOfferProject` and the rolled-set offer. So:

  an agent opens a log over the socket → Follow is on → the file rotates → the reload re-opens as
  HUMAN → every dialog the socket path suppressed fires, with nobody at the screen.

This is not a corner. It is the flagship path in spec-agent-brokered-dev-loop: *edit → approve
restart → watch the live log move in the analyser*. A restart rotates the log; the rotation is where
the modal lands; and a modal on that path is guaranteed to go unanswered. The record built to route
load-time side effects by audience discards the audience on the one open the product's headline
demo performs.

THE TEST PINNED IT. OpenRequestTest asserted `assertFalse(OpenRequest.reload("risk")
.fromActionSocket(), "a follow reload is human-context")`. A test asserting the wrong thing is worse
than no test: it makes the behaviour look deliberate and reviewed, and it would have failed the fix.

FIX (here): `reload(OpenRequest original, String provenance)` keeps BOTH answers — what was declared
and who asked. MainFrame remembers `currentRequest` when a load LANDS and the rotation reuses it.
That field re-introduces nothing of R1: it is written at the end of a completed load and read only
by the follow timer, never consumed mid-load. Test corrected to assert both directions plus the
null-original case.
