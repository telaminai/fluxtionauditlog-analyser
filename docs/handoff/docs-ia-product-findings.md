# Product findings from the docs restructure (for the owner)

The docs restructure (branch `docs/site-restructure`) changes no product behaviour. While checking the pages against
the code, it found the issues below. Each needs its own reviewed PR, because each changes what the product does or
says. Until then, the docs describe today's behaviour exactly.

| # | Finding | Evidence (at the restructure's HEAD) | What the docs say today | Suggested fix |
|---|---|---|---|---|
| P1 | **`graph {delete}` permanently deletes a saved chart's definition without asking**, for external MCP/REST clients and for the in-app assistant. The person's own *Delete chart* in the Graph tab asks first (OK / Cancel). The verb is not marked destructive for MCP clients, and Safe analysis pre-allows `graph`. Claude Code in the analyser is the one caller refused: its listener refuses `graph {delete}` outright. | `llm/VerbSchemas.java` (`delete`: "NOT recoverable (unlike a report delete)"); `mcp/McpTools.java` (`DESTRUCTIVE` excludes `graph`; `HOSTED_PRE_ALLOWED` includes it); `net/ActionServer.java:401-405` (the hosted refusal); `ui/GraphTabs.java:772` (the person's confirmation) | Start here: deleting a saved chart's definition is not reversible. *Diagnose an incident*: "`graph {delete}` removes a saved chart's definition for good, and it is not marked destructive". Verbs: "Not recoverable." The security model and the verbs reference say it cannot be undone and is not asked about | Mark `graph {delete}` destructive for MCP clients (so a client prompts first), or make the delete recoverable as report deletes are. Add a regression check either way (rule 8). |
| P2 | **A stale tooltip on a start-page fallback button.** *Evidence bundles guide* has the tooltip *"Help ▸ User guide ▸ Evidence bundles"*, but the button opens the docs site's *Opening a bundle you were sent* page (`evidence-bundles/opening/`), not the in-app Help ▸ User guide. | `src/main/resources/…/assistant/AskCatalogue.properties:141` (`fallback.bundleGuide.tip`); `ui/StartPanel.java:301` (`openUserGuide("evidence-bundles/opening/")`) | Nothing: the docs name the button, not its tooltip | Change the tooltip to say it opens the docs site's page on opening a bundle. `StartPanelNamesTest` already pins the action; pin the tooltip beside it. |
| P3 | **A shared settings file can switch on *External MCP/REST access*.** *Project ▸ Export settings…*'s *Assistant* category, ticked by default, writes `assistant.rest` (External MCP/REST access) and `assistant.inProcess` (*Let the in-app assistant change the views as it answers*) with the two caps; *Import settings…* applies them to this machine when the category is ticked. Settings ▸ Assistant's own note says every option on that tab is "this machine's and this user's only — never in a project, a shared settings file or a bundle". A project profile does not carry them. | `config/SettingsShare.java:237-242` (export), `:518-527` and `:644-649` (import); `Category.ASSISTANT` is `defaultOn`; `ui/ConfigPanel.java` (the Assistant tab's note) | *Projects, profiles and sharing* and *Security model* say what the category carries, and that importing it can turn External MCP/REST access on | Drop `assistant.rest` (and probably `assistant.inProcess`) from the shareable whitelist, on export and on import, so a received file cannot open a listener. Pin it in `ShareDisclosureContractTest` (rule 8). |
