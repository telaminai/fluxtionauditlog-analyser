# Host operations

Use the project root as the working directory. The effective configuration is [server-config.yml](../config/server-config.yml); Maven pins Mongoose 1.0.29 and plugins 1.0.43.

## Deploy, start and stop

Build with the build runbook. For local deployment, copy the built project with its configuration and required input files to an explicitly selected local directory, then run `java -jar target/preview-preflight-1.0.0-SNAPSHOT.jar` there. Remote/service-manager deployment is not supplied. Run in the foreground and use Ctrl-C for the generated shutdown hook to stop the server and close services. The bundle also supplies ../stop-server.sh and ../export-audit.sh; follow README for their registry/capture prerequisites.

## Input ordering and reset

Events whose relative order matters must share a supported ordered input route or an explicit upstream sequencer. Independent feeds do not promise deterministic interleaving. Inspect each selected connector and read strategy in the descriptor before running.

| Operation | Changed state | Retained state / position |
|---|---|---|
| ./mvnw clean | target build outputs | Source, external feeds and audit directory remain; this is not a feed rewind |
| Ctrl-C then java -jar target/preview-preflight-1.0.0-SNAPSHOT.jar | Process and in-memory objects | Persistent connector positions and files depend on the selected connector; restart is not a promised rewind |
| Feed reset / recorded-session replay | No generic command supplied | Read the selected connector/plugin contract; preserve evidence before any explicit destructive operation |

Pre-start cached delivery, if supported and enabled by the selected connector, is not durable session replay. A publisher may advance a shared cache read pointer after dispatch: late subscribers do not receive an already-consumed prefix. Do not assume a cache is a rereadable buffer. No replay recorder is enabled by analyser support.

## Audit and evidence

Capture is requested by this descriptor; verify the configured service is installed and each processor is recording before expecting data.
The effective descriptor below names the configured directory (relative to the host working directory), backend, roll size, retention and processor auto-start where enabled. Installation alone is not per-processor recording. Retention may remove earlier evidence; preserve an export before cleanup. Capture storage and analyser-readable YAML/JSONL exports are different artifacts.

```yaml
# Mongoose server descriptor — generated by the Fluxtion project starter.
# Boots via MongooseMain (MongooseServer.bootServer). Each feed/handler runs on the
# agent thread named by its agentName, looping with the configured idleStrategy.

# Event handlers — your processor(s), grouped by the agent thread they run on.
eventHandlers:
  - agentName: processor-agent
    eventHandlers:
      marketProcessor:
        # Supplier<DataFlow> — Mongoose calls get() to build the Fluxtion graph
        # (aot); the same builder also drives the standalone app.
        eventHandlerBuilder: !!com.acme.preview.builder.MarketProcessorSupplier {}

# Agent threads — long-running cooperative workers; each loops with an idle strategy
# (and optional CPU-core pin). Feeds/handlers above reference these by agentName.
agentThreads:
  - agentName: processor-agent
    idleStrategy: !!org.agrona.concurrent.SleepingMillisIdleStrategy {}

  - agentName: feeds-agent
    idleStrategy: !!org.agrona.concurrent.SleepingMillisIdleStrategy {}

# Event feeds — inbound sources. Each runs on its agentName thread; broadcast fans
# every event out to all processors on that agent.
eventFeeds:
  - name: input
    instance: !!com.telamin.mongoose.connector.file.FileEventSource
      filename: data/input.txt
      readStrategy: EARLIEST
    broadcast: true
    agentName: feeds-agent
    valueMapper: !!com.acme.preview.mapper.CsvToPriceEvent {}

# Event sinks — outbound destinations processors publish to.
eventSinks:
  - name: output
    instance: !!com.telamin.mongoose.connector.file.FileMessageSink
      filename: data/output.txt

# Performance monitoring — per-node counters + optional Chronicle-backed audit capture
# (records every event for deterministic replay via the admin console / visualiser).
performanceMonitoring:
  enabled: true
  counterBufferKb: 256
  latencyHistograms: true
  auditCapture:
    enabled: true
    backend: chronicle
    rollSize: 64m
    retainHours: 24
    directory: ./audit
    autoStart:
      - marketProcessor

# Services — shared singletons (admin console, server control, registries, caches…).
services:
  - name: adminCommandRegistry
    serviceClass: com.telamin.mongoose.service.admin.AdminCommandRegistry
    service: !!com.telamin.mongoose.service.admin.impl.AdminCommandProcessor {}

  - name: serverAdmin
    service: !!com.telamin.mongoose.service.servercontrol.MongooseServerAdmin {}

  - name: adminWebService
    service: !!com.telamin.mongoose.plugin.svc.adminweb.WebAdminService
      host: 127.0.0.1
      listenPort: 8181
      sourceRoots:
        - src/main/java
      serverName: preview-preflight
      environment: dev

```

For capabilities not configured here, consult the version-compatible [Mongoose plugin documentation](https://telaminai.github.io/mongoose-plugins/) before adding commands or making replay/reset claims.
