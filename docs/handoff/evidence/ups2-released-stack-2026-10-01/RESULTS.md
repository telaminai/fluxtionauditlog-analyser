## What changed

- **Pins.** Both poms now pin runtime **1.1.0** and builder **1.0.76**, the pairing Mongoose used for its committed 1.1.0
  fixture against the same hosted generator:
  - the root pom's `fluxtion.version` and `fluxtion.builder.version`;
  - `examples/fixture-generator`'s, which `FixtureGeneratorToolchainTest` holds equal;
  - `PomShapeTest`'s version tripwire, `1.0.16` → `1.1.0`;
  - the replay runner's JBang `//DEPS` (`tools/replay/ReplayBundle.java`), which `ReplayRunnerEndToEndTest` holds to
    the analyser's runtime.
- **The session processor** was regenerated with `mvn -Pregen process-classes`. It already implemented
  `runInEventCycle` on `main`, so only its toolchain stamp changed (api 1.1.0, analyser 1.0.76): 3 lines in each source
  copy and 1 in the GraphML.
- **The DEMO processors** were regenerated by `examples/fixture-generator` (`DemoQuote`, `DemoQuoteTraced`,
  `DemoQuoteRecorded`). They gain the 1.1.0 `runInEventCycle` method and the new toolchain stamp, and nothing else.
- **The fixture generator now strips both the attribution and the confidentiality notice automatically**, as the root
  `regen` profile strips the attribution.
  - Every regenerated file came back with an attribution line carrying an employer-domain address, which
    `GeneratedSourceIsPublishableTest` would have failed on, and with a confidentiality notice (fluxtion#24, M19.22).
    On `main` the DEMO fixtures carried neither: both had been stripped by hand.
  - Two fresh regenerations after automating it carried neither.
