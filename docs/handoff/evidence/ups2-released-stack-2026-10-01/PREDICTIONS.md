## Toolchain, read before deciding (rule 6)

The pairing is the one Mongoose generated its committed 1.1.0 fixture with against the same hosted generator:
runtime **1.1.0**, builder **1.0.76**, `fluxtion-maven-plugin` 1.3.0 (mongoose `design-doc/admin-gen/README.md`). A
builder that does not match the hosted generator emits a processor that compiles and audits nothing (R0, 2026-09-28,
`FixtureGeneratorToolchainTest`). 1.1.0 adds `DataFlow.runInEventCycle`, which `DefaultEventProcessor` and processors
generated by 1.0.76 implement.

## Predictions

- **S1.** The regenerated session processor and DEMO processors implement `runInEventCycle`. Otherwise their dispatch
  is unchanged, so the session's behaviour and every session test are unchanged.
- **S2.** The regenerated topology fixtures have the same records, the same node ids and the same node-log values as
  now. Only the generator header changes (api 1.1.0, analyser 1.0.76), so the field-by-field comparison against `main`
  is empty, apart from fields that carry the toolchain version. The fixture generator pins the clock.
- **S3.** The regenerated replay fixtures replay exactly as now, and every M70 replay test passes unchanged.
- **S4.** `PomShapeTest`'s tripwire fails at `1.0.16` until it is moved to `1.1.0`, as designed.
  `FixtureGeneratorToolchainTest` passes, because both poms move together.
- **S5.** The full headless suite, the 41 frame suites and the full mutation gate stay green. The counts equal the
  baseline measured on `main` before any change: **3084 / 0 / 0 / 218 across 406 reports, no orphans**. A preflight anchor in the generated GraphML or source may move with
  the regeneration; if it does, it is re-derived by meaning and named.
- **S6.** The generated source carries no employer attribution: the `regen` profile strips it, and
  `GeneratedSourceIsPublishableTest` holds that. The public-data sweep is clean.

A prediction that fails is recorded as failed, with what was found.
