## Timing and capture

The transcript is the evidence of record. Record UTC, awake monotonic and suspend-inclusive
continuous times at receipt. Continuous elapsed controls caps. macOS uses mach_continuous_time;
Python monotonic uses mach_absolute_time, which pauses in sleep. Keep an idle-sleep assertion
while a trial runs, release it afterward. A >1s continuous/awake gap or >0.1s UTC/continuous
drift invalidates uninterrupted timing claims, not the retained functional evidence. Never
subtract waits to make a client look fast. The 60s child-process clock probe must pass before T1.
Visible text/tool events are projected; private thinking/signatures and credential values are not
published. Environment ASK/intervention messages are preserved verbatim. Target zero substantive
interventions. Normal termination does not by itself establish task success.

## Routing denominator, fixed in advance

The unit is each assistant message containing one or more tool calls (a tool batch). Every batch
counts, including failures, navigation and repeated calls. A visible `from:` line since the previous
batch supplies at most the next batch. Missing, invalid or conflicting lines => UNATTRIBUTED;
never drop that batch or impute an explanation from file reads. A pointer to an unseen artifact is
UNVERIFIED. Record actual file reads separately. Repeated declarations without a following batch
are not additional denominator units. No request for private reasoning or narrative justification.

Classify shipped runbook/readme/contract/error/stub pointers as ROUTED when the referenced artifact
was observed before the action; example pointers retain the exact copied path and require manual
classification. search/prior/operator/task/unattributed/unverified and unresolved examples stay
in the denominator and out of the routed numerator. Report categories and total, routed/total,
and unattributed/total. Do not compare numerically with the historical self-journal denominator.

All compatibility R2 runs were repeats of ONE applicable task. They establish no different-task
recurrence. Product routing adoption still requires two independent sessions on different applicable
tasks; this battery will report by task and cohort, not pretend six variants are six task types.
Static fingerprints use the repaired scorer's code plus pristine acquisition baselines and are
reviewed manually; no fake journal to produce a timing/routing score.
