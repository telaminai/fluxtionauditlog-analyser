## Recording

- Fresh CLI process, no session/history reuse; only downloaded project and public dependencies.
  OS probes must deny source checkouts and staged answers before the first trial. No analyser MCP
  or private generation provider. The authenticated client subscription is an environment capability.
- Give the sealed task once. No mid-task coaching, repair, retries or follow-up prompt. Environment
  answers are logged verbatim as ASK; all other interventions make the task assisted.
- Ask for a short visible `step: N; from: <relative path | task | prior>` before each numbered step.
  No journal, invented clock times, hidden reasoning, or reasoning extraction is requested.
  Pointers are declared attribution. Record observed file reads separately; neither proves causality.
- Preserve raw transcript privately. Publish only visible text and tool events, with operator
  monotonic receive time and raw line number. Times bound when output was received, not the exact
  instant a filesystem operation happened. The process timer is the duration authority.
- Stop on the FIRST provider refusal and record it as incompatible for this task/configuration.
  Do not continue a rejected request or interpret a later successful command as erasing the refusal.
- Client output is testimony. Independently check build status, exported values, ordering, file
  identities and shutdown. Missing data is not a pass. A configured empty sink is not sink coverage.

## Frozen compatibility matrix and rubric

Three independent positive trials, in order: R2-1 opus, R2-2 sonnet, R2-3 opus, each on its own
pristine copy with a provisioned public Maven cache. The task has six input scenarios and a checker
negative control; meaningful work, no deliberate delay. Cap: 600 seconds each. Models are requested
aliases; record actual provider model IDs. This tests two model levels on one CLI/provider, not two
independent client implementations.

A functional PASS requires no provider refusal, normal completion, all six independently checked
scenarios, checker rejects its intentionally wrong expected value, originals unchanged, no substantive
intervention, and no surviving server. Partial completion is INCOMPLETE, not a pass. Environment
failures stay separate and are not silently rerun in this matrix.

Duration coverage is a separate gate: at least three refusal-free completed positive trials lasting
240 seconds or longer. Faster successes remain functional passes but do not qualify the late-failure
window; do not pad them or silently relax this threshold. This threshold is an operational screen,
not a statistical reliability claim. Failure or insufficient duration leaves the battery on hold.

One negative trial R2-4 opus, cap 180 seconds: an actual generated project explicitly requesting no
launcher. PASS means it cites the absence and stops without inventing/executing a launcher or editing
the project. This tests the deliberate decline branch, not the ordinary catalogue defaults.

The battery remains gated separately on a target/capability combination representative of beta
(including generation where tasks need it), public acquisition if claimed, T5 availability if scored,
sealed held-out inputs/oracles inaccessible to subjects, and a manual correctness review. Successful
operator generation establishes that route today, not that a keyless beta tester can use it.
