# Audit logs and evidence

Audit and evidence track. Entry 1 is a PLACEHOLDER (example owner, all-zero commit): pin a real commit before use.

1. **Teaching example: the diamond (placeholder)** — example: https://github.com/example/fluxtion-diamond/archive/0000000000000000000000000000000000000000.zip
2. **What does a record show?** — Pick one record on screen and explain each part: the event, the times, the thread and the node logs. Which values did a node write itself, and which did the framework add? Please use the analyser's log format pages and the Fluxtion audit docs, and tell me if you can't tell from what's here.
3. **Audit levels: INFO versus TRACE** — What does the audit level change about what gets written? At the level this log was written at, would a node that ran but logged nothing appear at all? Can you tell from these records which level was in force? Check against the docs and the records, and tell me if you can't tell from what's here.
4. **What silence means** — Which nodes never appear in this log? For each one, can you say it didn't run, or only that it may have run without logging? Explain from what the records carry and the format specification, and tell me if you can't tell from what's here.
5. **Is the order in a record meaningful?** — Is the order of the node entries in a record the order they ran in? What does the analyser say about ordering for this log, and what would be different for a log from another engine? Check against the format specification, and tell me if you can't tell from what's here.
6. **Flags, reports and walks** — I've found something in this log. What's the difference between flagging a record, writing a report and saving a spotlight walk? Which of them would someone else see if I sent them this investigation, and which stay on my machine? Answer from the analyser's docs, and tell me if you can't tell from what's here.
7. **Packing an evidence bundle** — I'd like to send this investigation as an evidence bundle. Before making anything, explain what would go in it, what would be left out and why, and when the analyser would refuse to make one. Then ask me before you write it. Answer from the evidence bundle docs, and tell me if you can't tell from what's here.
8. **Checking a bundle I was sent** — Someone has sent me a .fexp file. How do I check that it hasn't changed, and what does a successful check prove and not prove? What should I compare with the sender, and what won't the bundle let me do? Answer from the evidence bundle docs, and tell me if you can't tell from what's here.
9. **Trust the evidence, not the author** — In this investigation, which statements are backed by a record, a chart or the generated code, and which are only someone's account, including yours? Point at the evidence for each one, and tell me if you can't tell from what's here.
