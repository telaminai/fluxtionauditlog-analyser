# M78 — The quiet assistant panel

**Status:** ACCEPTED, 2026-10-18. The owner accepted every recommendation, OD-Q.1–.12, on 2026-10-18 (*"Yes to
changes"*, §9). Written from a UX review of the docked assistant panel on `feature/claude-code-p3` @ `bc015ea2` (M74
P3 with the UX unification). The review drove the real panel through 13 states in light and dark at the default window,
dumped every visible component, and mocked the proposal state by state. The mocks and the dumps are review scratch and
are not committed (CLAUDE.md rule 1: screenshots are generated by the capture harness, never hand-taken). §4 gives the
layout in words and ASCII.

**Tracker:** M78. **Builds on:** M74 ([`spec-claude-code-provider.md`](spec-claude-code-provider.md): the panel, the
postures, the permission dialog, the consents, the folder trust) and M77
([`spec-ai-setup-wizard.md`](spec-ai-setup-wizard.md): OD-77.3, the quick switch that replaces the profile cards, §6.6,
the panel when nothing is set up, and P-3, the docked layout floor). CLAUDE.md rules 1, 8 and 9 apply.

**Owner principle (2026-10-18).** *"In the onboard assistant there is too much text and drop downs; in normal use they
will be ignored, especially the text."* **Design for the 50th use, not the first.** A sentence a person reads once
belongs where it is read once, such as a dialog, a tooltip or *About this session…*. A signal a person needs every time
stays visible, in as few words as carry it.

---

## 1. The problem, with numbers

At the default 1200×800 window the docked panel is **216×431 px**. The default window is therefore the narrow case, and
the panel is laid out for a much wider one. The review counted the panel's chrome (every visible label, button and text
area outside the transcript and the composer's own text; tooltips excluded) in each state:

| State | Visible chrome words | Visible buttons |
|---|---|---|
| Ready, Safe analysis | 33 | 6 |
| Ready, Full Claude Code | 43 | 6 |
| Safe, not yet started | 61 | 7 |
| A turn running | 30 | 6 |
| A permission request waiting | 46 | 6 |
| Claude Code exited (error) | 46 | 7 |
| In-app, no API key | 72 | 8 |
| A record's Ask draft placed | 80 | 6 |
| A wide answer with *About* open | 118 | 8 |

The review inventoried **47 elements**: chips, lines, buttons, banners, notes and dialogs. Most of them repeat what
another element says, or say once-only things on every use:

- One sentence of **40 words** (*"Not running. Send starts Claude Code first — contacts Anthropic…"*) sits in the panel
  before every first Send.
- A **25-word** waiting sentence repeats what the permission dialog already shows.
- The Safe limits line (`LocalAgentPanel.SAFE_LIMITS`) is **59 words**, and the restart banner is **48 words**.
- The Full badge is **13 words**, and at 216 px it is cut off with an ellipsis.
- A **12-word** *"Approved: …"* note repeats the tool line's *"approved by you ✓"*.
- Every answer carries *"the model's words, not a verified result"*, and every turn carries *"Turn: 6.1 s"*.
- The header stacks up to five rows of chips: *Claude Code*, the model, the posture, the billing kind and *"usage
  counts against your Claude plan"*. At 216 px the model chip and the plan chip are clipped, so the plan disclosure,
  the one chip with a reason to exist, cannot be read (defect 2, §8).

With all this chrome, the answer starts below the fold, the header scrolls, and the controls that matter (the mode, the
attention state and Send) are some of the 6–8 controls on screen.

## 2. The principle

1. **Always visible** means needed on every use: the mode, an attention word, the composer, one primary action, and the
   two safety signals of §3 (Full is on; the answer is unverified).
2. **⋯** holds what is used occasionally: *New chat* (also the ✎ icon), *Pop out*, *About this session…*, *Switch
   assistant…*, *Start / Resume*, *Set up a project…* and *Settings…*.
3. **Conditional** elements appear only while their condition holds. These are the banners (restart, error, no key,
   external access, proposal), *Details* while attention is set, *Stop* while a turn is busy, the binding chip on a
   mismatch, and *"Draft — not sent"* while a draft is unsent. Each disappears when its condition clears.
4. **Once-only text** goes to the moment it is read once: the first-Start folder-trust dialog, the PLAN note on a
   session's first READY, the Full consent each time Full is turned on, or *About*.
5. **Nothing is composed in the panel** (rule 9). Every word the panel shows comes from a session node's snapshot,
   §5. A moved sentence keeps its constant; only where it is rendered changes.

Quieting the panel removes no signal. Each of the following is kept, and several become harder to miss because they no
longer compete:

## 5. Rule 9: every word from the snapshot

Nothing in this spec is decided or composed in the panel. Each change is a node, an effect or a fact, then a regenerate
(`mvn -Pregen process-classes`).

### 5.1 `Guide.chipWord`

`LocalAgentState.Guide` (today `primary`, `instruction`, `action`, `refusal`, built by `LocalAgentSession.guide`) gains
**`chipWord`**, a closed set: `""` (Ready), *"answering…"*, *"needs you"* and *"stopped"*. `localAgentSession` sets it
from the session state; **the permission node's waiting state (`localAgentPermission`) maps to *"needs you"***. For the
in-app assistant (D2) `assistantLoop` publishes the same field. The panel renders *"Safe · needs you ▾"* by joining the
mode word and `chipWord`; it never picks the word. A new word is a change to the node and its test (TQ6), not to the
panel.

### 5.2 The PLAN note

`localAgentSession` appends one transcript note with status `PLAN` **on a session's first READY**. A restart starts a
new session, so it appends one again. The note's sentence comes from the node's lines (for example *"Claude Code · Safe
· uses your Claude plan"*), and `noteLabel` gives `PLAN` no label, so the sentence stands alone. With an API key the
note carries no cost. A cost note (the existing `BUDGET`, *"Spend limit"*) is appended only near or at the limit.

### 5.3 The Approved note is dropped by the node

`LocalAgentPermission` stops calling `permissionNoted(ticket, "APPROVED", …)`. The tool line's outcome
(*"approved by you ✓"*, `TranscriptStyle` `APPROVED`) is unchanged. `DENIED`, `TIMED_OUT` and `WITHDRAWN` notes are
still appended. The panel's `noteLabel` loses its dead `"APPROVED"` case. **The panel does not filter the note**: a
filter in the view would be a hand-placed decision, the thing rule 9 rules out.

### 5.4 The rest

- **Conditionals** (Details, Stop, the binding chip, *"Draft — not sent"*, the banners) render from fields the snapshot
  already has: attention, busy, the binding verdict, the draft state, the restart offer. Where a field is missing, it
  is added to the node, not derived in the panel.
- **OD-Q.6, the quick switch:** with no turn running, the switch applies and restarts at once with no banner. With a
  turn running, the node offers the restart banner. The decision is the profile node's (M77's `aiSetup`), not the
  menu's.
- **Moved sentences keep their constants** (`SAFE_LIMITS`, `NOT_VERIFIED`, `AssistantProfiles.CLAUDE_CODE_SENDS` /
  `IN_APP_SENDS`). Only the surface that renders them changes.
